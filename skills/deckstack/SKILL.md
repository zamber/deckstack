# deckstack

Start at `AGENTS.md`, then `docs/00-scope.md` (alpha scope invariants), `PLAN.md`, and
`docs/contracts/` + `schemas/` (normative contracts). Read order, invariants, commands,
worktree/PR protocol, definition of done: `AGENTS.md` and `docs/AGENT-WORKFLOW.md`.

## Ticket lifecycle (all commands real, proven on DS-000)

```sh
sh tools/bootstrap.sh                     # setup: .venv + requirements + tools/check.sh
sh tools/setup-review-remote.sh           # once per clone: local `review` remote (.review.git), push main
python3 tools/tickets.py ready            # ready set (deps done, claimable)
sh tools/wt.sh new DS-XXX --owner <name>  # claim + .worktrees/DS-XXX on branch ticket/DS-XXX from main
cd .worktrees/DS-XXX && git add -A
# commit: git commit -m "ticket(DS-XXX): <subject>" -m "Generated by Mistral Vibe." \
#           -m "Co-Authored-By: Mistral Vibe <vibe@mistral.ai>"
sh tools/pr.sh submit DS-XXX              # checks + prs/DS-XXX.md + push to review
# steward on main: sh tools/pr.sh review DS-XXX --approve ; sh tools/pr.sh merge DS-XXX
# inspect: sh tools/wt.sh list ; sh tools/pr.sh list ; python3 tools/tickets.py recover
```

Rules of thumb: Linux-only alpha; empty state, no presets; no `ds migrate`, no web UI;
contracts change together with schemas (`sh tests/fixtures/validate.sh` must print ALL
CHECKS PASSED); never commit feature work to `main` — one worktree per ticket under
`.worktrees/<id>`, branch `ticket/<id>`, PR record `prs/<id>.md`; edit only your ticket's
`touches` (update the ticket via `tools/tickets.py` first if scope changes); never edit
`BRIEF.md` R1–R12, `docs/discovery/`, `docs/reviews/`; ticket metadata only via
`tools/tickets.py` (never hand-edit the JSON block or the generated BOARD/GRAPH/index);
the gate is `sh tools/check.sh`; the steward role is `agents/deckstack-steward.md`
(`sh tools/steward.sh "<task>"`).
