Architecture

One process writes to the deck. Everything else talks to it.

Process model

ds-daemon owns the HID device, the state document, the binding router, the frame writer and the plugin host. The CLI, the MCP bridge, the focus sender and any program you write connect to a Unix socket. They are peers. None of them has privileged access to the device.

Every client speaks the same protocol and has the same rights. There is no UI process and no privileged client in the alpha. A program that can open the socket can use the daemon. A token scope decides what it may do.

Control plane and frame plane

Screen writes and state changes travel on different sockets with different encodings. That split is the reason a 32 fps frame stream does not stall a query.

A frame push updates no durable state and no revision. The daemon writes frame statistics into /telemetry at most once per second. At 32 fps there are zero state transactions and zero /controls events per frame.

The writer sends a picture whole. It replaces only the waiting slot and never the frame in flight. Abandoning a chunked transfer tears the image on the module.

Input to behaviour

A key press becomes an input report. The router looks up bindings for the topic. A binding is a list of steps. Each step has one effect.

set writes a state path, increments the revision, notifies subscribers and checks whether a repaint is due. emit publishes a topic on the event bus, including to external clients. plugin sends an action to a plugin process and applies the effects it returns. exec runs an absolute argv under the exec policy. sleep delays the next step.

A focus change follows the same route. ds-focus emits app/focus/changed, a binding matches the topic, and the steps recolor keys or write a label. The daemon does not link against Wayland.

State and revisions

The daemon holds one JSON document. Paths address it. Examples are /controls/keys/0/image, /settings/dim, /policy/net/allow_hosts and /plugins/lights/state/config.

Each durable write increments rev. A write can carry if_rev. If the document has moved, the daemon refuses with E_CONFLICT and returns the current revision. Subscriptions match path patterns. Events carry the revision that produced them, so a client can detect a gap.

Frames live outside this document. They are not state, they do not bump rev, and they do not appear in /controls subscriptions.

Write path and policy

ds-device is the only path to HID. The protocol crate makes forbidden commands unrepresentable, and the device layer checks the policy document before any byte leaves the host. The check covers screen writes, LED writes and the software mode handshake.

  • Exec steps use an absolute argv, with no shell. The binary must be in /policy/exec/allow and not in /policy/exec/deny. The daemon applies rlimits, a working directory inside the allowed roots, and a timeout.
  • Plugins declare capabilities in their manifest. Network requests go through the daemon, which matches the URL host against the plugin grant and /policy/net/allow_hosts before it connects.
  • Tokens carry the scopes read, mutate and admin. The install token is admin. Scoped tokens are defined by the contract, and the ds token verb that issues them is later-phase.
