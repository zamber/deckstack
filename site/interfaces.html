CLI

ds is stateless. Each call connects to the daemon, sends one request, prints the result and exits. ds watch holds a subscription open and prints one JSON object per line.

ds [--socket PATH] [--token-file PATH] <verb> [args] [flags]
ds --help | ds <verb> --help
ds schema <state|ipc|stream-frame|plugin-manifest|binding>
ds describe <path>
VerbWhat it doesStatus
getread a state path, with optional fields and expected revisionworks
setwrite a state path, from JSON, a scalar or a fileworks
colorswrite 15 key colours in one revision and one panel pushworks
watchsubscribe to a path or topic and stream eventsworks
schema describeself-description for agents and for peopleworks
status daemondaemon status, start, stopworks
bind unbindappend or remove a binding on an event topicworks
streampush, stats, stop for the frame planepush is wired, the daemon does not bind the frame socket yet
emit events plugin tokenlater-phase verbsrefused with exit 1

Exit codes are part of the contract. A script can tell a usage error from a conflict or an unreachable daemon without parsing the message.

CodeMeaning
0ok
1usage or schema error
2E_PATH, path not found or bad syntax
3E_CONFLICT, if_rev did not match. The payload has current_rev.
4E_AUTH, E_SCOPE or E_CAP
5E_LIMIT
6E_UNREACHABLE. The message includes the daemon start command.
7E_DEVICE, including forbidden commands
8E_INTERNAL or E_VERSION

Control plane

The control socket is newline-delimited JSON. One request line carries an id and an op. One response line carries the same id and either ok: true or an error object.

ItemValue
Socket$XDG_RUNTIME_DIR/deckstack/daemon.sock, falling back to ~/.local/state/deckstack/daemon.sock
Permissionsdirectory 0700, socket 0600, token file 0600
First exchangehello with protocol 1, answered by welcome with the current revision
Authauth with the install token and a requested scope
Opsping, hello, auth, get, set, subscribe, unsubscribe, emit, bind, unbind, plugin, stream-open, stream-stats, stream-stop, daemon, token, schema
Limits1 MiB request line, 4 MiB response, 64 in flight per connection, 300 s idle timeout, 64 connections

A request that is not one schema-valid object is answered with E_SCHEMA. A line over the cap is answered with E_LIMIT and the connection closes, because the framing can no longer be trusted.

{"id":0,"op":"hello","protocol":1,"client":"manual/1.0"}
{"id":0,"op":"welcome","protocol":1,"rev":41,"daemon":"0.1.0"}
{"id":1,"op":"auth","token":"...","scope":"admin"}
{"id":1,"ok":true,"rev":41,"result":{"scope":"admin"}}
{"id":2,"op":"get","path":"/controls/keys/0/image"}
{"id":2,"ok":true,"rev":41,"result":{"kind":"color","value":"#3cc86e"}}
{"id":3,"op":"subscribe","path":"app/salon/key/*"}
{"id":3,"ok":true,"rev":41,"result":{"subscription":"s0001"}}
{"id":3,"event":"app/salon/key/0","rev":41,"payload":null}

Scopes are read, mutate and admin. The install token is admin. A request that needs a higher scope fails with E_SCOPE. A plugin request for a capability the manifest did not declare fails with E_CAP.

Frame plane

Frames do not travel as JSON. stream-open on the control socket authorizes a target and a credit budget. The frames themselves go to stream.sock as DSF1 records.

"DSF1" | u32 LE meta_len | JSON meta | u64 LE payload_len | payload

meta = {target, seq, ts_ms, format, w, h, frames, fps, loop, crc32,
        max_payload_bytes: 16777216}

Stream control lines on the same socket start with DSctl, so the two framings never mix. The producer respects credits. Each module queue holds one frame in flight and one waiting frame. A new frame replaces the waiting one.

The CLI exposes ds stream push, but the daemon in this tree does not bind stream.sock yet. Treat the frame plane as specified and tested in the vdev test setup, not as a finished path on hardware.

Plugins

A plugin is a separate OS process with a manifest. The host starts it, speaks newline-delimited JSON over stdio, and mediates every side effect. The plugin has no HID access and no ambient authority.

{
  "id": "lights",
  "command": ["python3", "plugin.py"],
  "actions": [
    {"id": "set", "name": "lights.set", "params": { ...JSON Schema... }}
  ],
  "capabilities": ["state.read", "state.write", "net:lights.lan"],
  "resources": {"cpu_s": 10, "nproc": 64, "nofile": 64, "as_mb": 1024}
}
CapabilityWhat the host enforces
state.readreads from the paths the manifest allows
state.writewrites to the paths the manifest allows
net:<glob>the URL host must match the grant and /policy/net/allow_hosts. The daemon makes the request.
fs:<root>the process gets that root, and only that root, through the sandbox

The Python SDK keeps the wire protocol out of the plugin. The lights plugin is one action and one serve call.

import ds_plugin_py as sdk

SET_PARAMS = {
    "type": "object",
    "properties": {
        "room": {"type": "string"},
        "light": {"type": "string"},
        "brightness": {"type": "integer", "minimum": 0, "maximum": 100},
        "color": {"type": "string", "pattern": "^#[0-9a-fA-F]{6}$"},
    },
    "required": ["room", "light"],
    "additionalProperties": False,
}

@sdk.action("set", params=SET_PARAMS, description="Set a light in a room")
def lights_set(args):
    cfg = sdk.get_state("/plugins/lights/config")
    reply = sdk.http("GET", url_for(cfg, args))
    return [sdk.set("/plugins/lights/state/last", {"ok": True})]

sdk.serve(MANIFEST)

The host restarts a plugin that exits, with a bounded backoff. Plugin logs are kept per plugin. An action that fails returns an error object and no effects.

Agents

An agent uses the same control socket as the CLI. Three interfaces are ready today.

ds-mcp

A stdio JSON-RPC 2.0 server that implements tools/list and tools/call. Ten tools cover the daemon API.

ToolWhat it does
deck_statusdaemon status, revision, device and socket
deck_getread a state path, optionally at an expected revision
deck_setwrite a state path, optionally compare-and-set
deck_bindappend a binding with steps and an optional condition
deck_unbindremove a binding by id or topic
deck_emitpublish a topic on the event bus
deck_watchsubscribe and return events
deck_stream_pushpush a frame or a frame directory
deck_plugin_listlist installed plugins and their state
deck_schemareturn a contract schema
 
{
  "mcpServers": {
    "deckstack": {
      "command": "$HOME/Applications/deckstack-0.1.0/bin/ds-mcp",
      "args": ["--data-dir", "$HOME/.local/state/deckstack"]
    }
  }
}

ds-focus

Publishes the focused window as app/focus/changed. A binding on that topic can recolor keys or write a label. ds-focus --quiet keeps it out of the terminal.

ds-py

A small Python client over the CLI. It never opens the socket itself, so the CLI contract stays the only interface it has to track. Client.watch() yields parsed events.

For any other language, the control socket is the interface. Open it, send hello, authenticate, and read or write state.
