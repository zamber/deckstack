## Context

Post-alpha backlog (docs/00-scope.md, ADR-014): the WS/HTTP adapter exists as a generic
transport for agents/debug clients only; a thin debug/web client is a post-alpha note,
not a plan item. ipc.md §1.1 specifies the adapter surface and its T7 protections.
This ticket stays backlog until alpha is stable.

## Goal

Keep the optional debug client as a scoped, safe post-alpha item — either a minimal
debug client over the adapter or a documented decision not to ship one.

## Scope

- Decide first: ship a thin `bins/ds-web` debug client (static assets, no logic) or
  document "adapter only, no client" as the final answer. Either outcome is acceptable;
  the ticket must end with an explicit decision recorded in docs/contracts/ipc.md's
  post-alpha note.
- If shipping: `new:bins/ds-web/` (serves /api/* proxy + /ws + static debug page),
  T7 protections, conformance under `new:tests/conformance/web/`.
- `docs/contracts/ipc.md`: post-alpha note updated with the decision (minimal edit).

## Out of scope

Any UI beyond a debug page, alpha deliverables, changes to the adapter's security
model, mobile clients.

## Implementation notes

Read docs/contracts/ipc.md §1.1, docs/00-scope.md invariant 3, ADR-014,
docs/20-security.md T7. The 421/401/404 behaviors are already contractual — implement
to them, don't redesign.

## Files and boundaries

Only `touches`: `new:bins/ds-web/`, `docs/contracts/ipc.md` (post-alpha note only),
`new:tests/conformance/web/`. Do not edit the adapter core in `crates/ds-ipc/` unless
the adapter itself is missing — then escalate, since the adapter belongs to phase 1.

## Acceptance

Decision recorded; if implemented, conformance web cases green and the scope guard
(404 at /, no business logic client-side) holds.

## Verification

See metadata (conformance when implemented; validate + stale-grep always).

## Risks

Scope creep into a real UI — the ticket explicitly forbids it; steward rejects such
PRs. Security regression via the adapter — T7 cases must be green before any client
ships.

## Definition of done

PR merged with either the thin client or a recorded no-client decision.

## Notes

Stays backlog; deps keep it after the stream plane exists.
