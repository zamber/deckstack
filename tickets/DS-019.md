## Context

The daemon is long-lived (PLAN.md); on Bazzite/Fedora it runs as a systemd user service
(docs/50-repo-topology.md §1 lists packaging/). The operator runbook is DS-064's phase-6
full version; this ticket is the phase-1 lifecycle minimum.

## Goal

A working `deckstack.service` user unit and a short runbook covering start/stop/status/
logs/recovery for the daemon.

## Scope

- `packaging/systemd/deckstack.service`: user unit, `ExecStart=ds daemon start --device
  <default>`, restart policy, runtime dir handling, hardening basics (NoNewPrivileges
  etc. as compatible with the socket paths).
- `docs/runbook.md`: operator commands (`systemctl --user start deckstack`, `ds daemon
  status`, log location, token location, recovery after crash — correlate with
  `tools/tickets.py recover` philosophy for agent work).
- Install path note (packaging/, later AppImage in DS-083).

## Out of scope

udev rules (DS-025), AppImage/release packaging (DS-083), full runbook (DS-064).

## Implementation notes

Read docs/components/daemon.md and docs/50-repo-topology.md §1. Default device: virtual
until DS-021 lands; the unit must take the device from an Environment line so hardware
swaps are config, not code.

## Files and boundaries

Only `touches`.

## Acceptance

Unit verifies clean; documented commands work on a systemd user session (or are marked
manual-fallback where no systemd exists, e.g. containers).

## Verification

`systemd-analyze verify`; manual smoke output in the PR record; check.sh; board
validate.

## Risks

User-session quirks (XDG_RUNTIME_DIR absent in some contexts) — document the fallback
path from docs/contracts/ipc.md §1.1.

## Definition of done

PR merged, unit valid, runbook committed, lifecycle reproducible.

## Notes

Phase 2 hardware tickets (DS-025) add udev; keep the unit device-agnostic.
