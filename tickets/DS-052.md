## Context

Phase 5 Python surface (roadmap phase 5 exit: ds-plugin-py installable from PyPI).
Contract: docs/contracts/plugins.md §6 (D09 wrapper) and §7 (the ~40-line example
plugin uses `import ds_plugin_py as sdk`). Repo boundary: repos.toml +
docs/50-repo-topology.md §0 — `deckstack-plugin-py` lives in-tree at `plugins-py/`,
published to PyPI, subtree-split later (DS-083). Host is DS-050.

## Goal

A Python package `ds-plugin-py` that lets users write plugins in ~40 lines (the
plugins.md §7 example must run) and can wrap an old hubdeck plugin class without
importing anything into the daemon.

## Scope

- `plugins-py/ds_plugin_py/`: SDK per plugins.md §8 — `serve(manifest)`,
  `@action(id, params)`, `sdk.set/emit/log`, `get_state/set_state`, `sdk.http(method,
  url)` → `request kind:"net"`, event loop over stdin newline-JSON, stderr logging.
- `plugins-py/ds_plugin_py/compat.py`: adapter for the old plugin interface
  (actions/states/values/invoke/adjust/set/watch/watch_states) → wire protocol;
  manifest generated from the class + pydantic models as JSON Schema.
- `plugins-py/pyproject.toml` + tests with a mock host; README showing the §7 example.
- `repos.toml`: verify the entry matches reality (in-tree plugins-py/, PyPI
  ds-plugin-py, subtree split + wheel) — edit only on drift.

## Out of scope

Host (DS-050), Rust SDK (DS-051), abuse tests (DS-053), example plugin docs
packaging (DS-054), actual PyPI publishing (DS-083/release), porting old plugins
(DS-071, post-alpha).

## Implementation notes

Read docs/contracts/plugins.md §6-8, repos.toml, docs/70-porting-notes.md. The wrapper
runs the old class in a dedicated child process (the package's own process) — the
daemon never imports old code. Keep the SDK stdlib-only where possible (JSON over
stdio) so plugin env stays minimal.

## Files and boundaries

Only `touches`: `new:plugins-py/`, `repos.toml` (drift fixes only). Do not edit
`crates/` (DS-050/051), `schemas/` (manifest schema is DS-050's), tests/conformance.

## Acceptance

The plugins.md §7 example plugin (counter + http action) runs against a mock host and
against the real host once DS-050 lands; wrapper translates a fixture old-style class
and its invoke produces correct effects; wheel builds.

## Verification

Python tests, wheel build, fixture gate, workspace cargo tests, conformance,

## Risks
