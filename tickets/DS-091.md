## Context

Parallel tickets change `Cargo.lock` and the generated ticket files (`tickets/BOARD.md`,
`tickets/GRAPH.md`, `tickets/index.json`, `tickets/DS-*.md`). Every parallel merge stops
in `tools/pr.sh merge` on those conflicts and needs the same hand resolution
(HANDOFF.md known issue 1). That resolution is mechanical and safe for these paths; the
rest must stay manual.

## Goal

`tools/pr.sh merge` resolves the known generated-file conflicts automatically during the
rebase, regenerates `Cargo.lock`, and only stops for a human when a path outside the
whitelist conflicts.

## Scope

- New `tools/resolve-rebase.sh <worktree>`: standalone, `sh`-only, drives an in-progress
  rebase in `<worktree>` to completion for whitelisted paths (algorithm below).
- `tools/pr.sh` `cmd_merge`: when `git rebase "$MB"` fails, run the resolver once in the
  worktree and continue only if it exits 0; otherwise die with the manual-resolution
  message and the worktree intact.
- New `tests/tools/test-resolve-rebase.sh`: self-contained regression test that builds
  throwaway git repos in `$(mktemp -d)`, creates the two conflict classes, runs the
  resolver, and asserts results. Must exit 0 and print `RESOLVE-REBASE: ALL PASSED`.
- `docs/AGENT-WORKFLOW.md`: replace the "Stops on conflicts" wording with the resolver
  behaviour and the manual fallback.

## Out of scope

- Resolving conflicts in source, contracts, docs, `prs/`, or `docs/run-log.tsv`; those
  remain manual.
- Adding a `tickets.py` subcommand (separate ticket if wanted).
- Changing the rebase/merge model itself.

## Implementation notes

Whitelist and rules (all resolved with `git -C <wt> checkout --ours -- <path>`: during a
rebase "ours" is the new base, i.e. main):

- `tickets/BOARD.md`, `tickets/GRAPH.md`, `tickets/index.json` — take main's version;
  the post-merge `tickets.py` calls regenerate them.
- `tickets/DS-*.md` (any ticket file, glob `tickets/DS-*.md`) — take main's version; the
  claim/review state on main wins, and `pr.sh merge` normalizes the merged ticket state
  afterwards.
- `Cargo.lock` — take main's version, then regenerate in the worktree with
  `cargo generate-lockfile --offline` (fallback to without `--offline` only if the caller
  exports `DS_LOCKFILE_ONLINE=1`). If regeneration fails, stop and report.

Loop: while `git -C <wt> diff --name-only --diff-filter=U` is non-empty, resolve each
path by the rules above; any non-whitelisted path means exit 3, printing the paths, and
leaving the rebase untouched. After staging all resolved paths with `git -C <wt> add`,
run `GIT_EDITOR=true git -C <wt> rebase --continue`; a new conflict restarts the loop; a
clean finish exits 0. Guard against a rebase that is not in progress (exit 2). Cap the
loop (e.g. 20 iterations) and fail loudly.

`cmd_merge` currently dies on any rebase failure. Change that block to:

```sh
if ! git -C "$ROOT/$wt" rebase "$MB"; then
  echo "== rebase conflict; resolving generated files with tools/resolve-rebase.sh =="
  sh "$ROOT/tools/resolve-rebase.sh" "$ROOT/$wt" || die "rebase conflict needs manual resolution in $wt; resolve, then re-run: sh tools/pr.sh merge $id"
fi
```

Test script shape (no network, no assumptions about the main repo):

1. Case A: temp repo with `tickets/BOARD.md`, `tickets/DS-901.md`, `Cargo.toml`
   (minimal package, no deps) and a `Cargo.lock`; branch `feature` changes all three on a
   commit; `main` changes the same three differently; `git rebase main` conflicts; run the
   resolver; assert exit 0, no unmerged paths, `tickets/DS-901.md` equals main's version,
   `tickets/BOARD.md` equals main's version, `Cargo.lock` was regenerated by cargo, and
   the rebase completed (`git rev-parse --git-path rebase-merge` absent).
2. Case B: same repo, a commit that also conflicts on `README.md` (outside the
   whitelist); assert the resolver exits nonzero, prints the path, and the rebase is still
   in progress with `README.md` unmerged.
3. Print `RESOLVE-REBASE: ALL PASSED` on success.

Cargo availability: the test must call `cargo` from `PATH`; skip case A's lockfile
assertion with a clear message if cargo is missing (the deckstack environment has it).

## Files and boundaries

Only the paths in `touches`. Do not modify `tools/tickets.py`, `tools/wt.sh`,
`tickets/*.md`, or any crate.

## Acceptance

`sh tests/tools/test-resolve-rebase.sh` → `RESOLVE-REBASE: ALL PASSED`; both scripts pass
`sh -n`; `sh tools/check.sh` green.

## Verification

`sh tests/tools/test-resolve-rebase.sh`; `sh -n tools/resolve-rebase.sh && sh -n
tools/pr.sh`; `sh tools/check.sh`; `python3 tools/tickets.py validate`.

## Risks

Wrong-side checkout: during rebase `--ours` must be main. The test asserts file contents,
not just exit status. Resolver loops must be bounded. `cargo generate-lockfile` needs the
local registry cache; keep `--offline` the default so a missing crate fails loudly instead
of hanging.

## Definition of done

PR merged, test green, `tools/pr.sh merge` uses the resolver, AGENT-WORKFLOW updated.

## Notes

HANDOFF.md known issue 1 has the manual recipe that this automates. Manual resolution
stays the fallback and will still be needed for source conflicts.
