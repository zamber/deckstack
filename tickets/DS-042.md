## Context

Phase 4 execution core. Contract: docs/contracts/actions.md §2-3 (closed vocabulary
set/emit/plugin/exec/sleep, ordering, recursion cap 10, when semantics S7). Component:
docs/components/event-router.md. Bindings storage/CLI is DS-041; the bus is DS-040.

## Goal

The router executes stored bindings: `when` gating plus the closed step vocabulary,
with ordering, recursion cap, and error events — all conformance-tested on vdev.

## Scope

- `router/when.rs`: condition evaluation against state (`path`) or event `payload`
  field; operators per schemas/binding.json; missing path → `exists: false`.
- `router/steps.rs`: step executors — `set` (validate against schemas/state.json then
  transactional apply), `emit` (publish + recursion depth counter, cap 10 then
  `deck/system/binding-error`), `plugin` (forward to plugin host; before DS-050 this
  returns a typed error — keep the seam clean), `exec` (call the DS-043 policy gate;
  before DS-043 the step must fail closed), `sleep`.
- Error handling: step failure → `deck/system/binding-error` event, remaining steps
  still run (event-router.md failure modes).
- `schemas/binding.json`: only if the step/when grammar needs tightening; update
  docs/contracts/actions.md in the same commit.

## Out of scope

Exec policy enforcement (DS-043), focus ingest atomicity (DS-044), plugin host (DS-050+),
CLI (DS-041), event bus (DS-040), benches (DS-045).

## Implementation notes

Read docs/contracts/actions.md §2-5, docs/components/event-router.md, schemas/
binding.json + state.json, ADR-007. The vocabulary is closed — unknown `do` fails
schema validation at bind time (DS-041) and at runtime. Never `eval` anything (T2).

## Files and boundaries

Only `touches`: the two router files, `schemas/binding.json` (minimal, with contract
sync). Do not edit `router/mod.rs`/`bus.rs` (DS-040), `router/ingest.rs` (DS-044),
`bins/ds/` (DS-041), `crates/ds-daemon/src/policy/` (DS-043).

## Acceptance

Conformance: a binding with `when` on payload fires only on matching events; multi-step
binding runs steps in order (observable via rev sequence); emit-loop hits the depth-10
cap with binding-error and the daemon stays healthy; `set` with a schema-invalid value
is rejected and state untouched.

## Verification

cargo tests, conformance bindings/actions cases, fixture gate, workspace tests,
conformance, check.sh, board validate — see metadata.

## Risks

Recursion cap off-by-one — unit-test depth 9 ok / 10 blocked. Fail-open exec before
DS-043 lands — the seam must return an error, never spawn; DS-043 replaces it.
