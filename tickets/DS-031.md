## Context

Phase 3 core service (docs/60-roadmap.md). Contract: docs/contracts/streaming.md §3-§6
(latest-frame-wins 1+1, in-flight never dropped — S16/M8; no per-frame rev — S1;
limits §5; stats §6). Component: docs/components/frame-service.md. The DSF1 stream
socket and credits come from DS-013; the daemon skeleton and device task from DS-015;
DS-020 proves the e2e vdev path this service plugs into. Encode/chunk from DS-030 is a
sibling file — do not edit it.

## Goal

The in-daemon frame service that accepts DSF1 frames, queues them per target with
latest-frame-wins, drives dedicated writer threads to the device, and exposes
`/telemetry/streams/<target>` — with zero durable-state churn per frame.

## Scope

- `service.rs`: stream-socket accept/validation, `stream-open`/`stream-ack`/
  `stream-nack`/`stream-credit` handling per ipc.md §2/§5, per-target queue (depth 2),
  256 MiB global frame-queue cap with drop counting, credits.
- `writer.rs`: one writer thread per target owning the device handle; sends whole
  frames via send_all (never abandons mid-chunk); paces to device ceilings
  (~32 fps accepted / ~2.1 MB/s) without blocking producers or the control plane;
  module-gone → frames dropped + counted + `deck/device/<serial>/disconnected` event.
- `telemetry.rs`: ≤ 1 Hz sampler into non-durable `/telemetry/streams/<target>`
  (`sent, dropped, fps, bytes, queue, in_flight, last_sha256, last_seq, writer_ms_p99,
  sampled_at`); reads carry no rev.
- Docs: update `docs/contracts/streaming.md` + `docs/components/frame-service.md` only
  if implementation reveals a contract gap — prefer conforming.

## Out of scope

Encode/chunk (DS-030), CLI verbs (DS-032), bench suite (DS-033), animation (DS-034),
vdev throttle knobs (DS-035), exec/policy (phase 4).

## Implementation notes

Read docs/contracts/streaming.md, docs/contracts/ipc.md §2/§5, docs/components/
frame-service.md, ADR-005. The anti-pattern to avoid is the old synchronous paint
(`hubdeck/.../engine.py:1325-1341`): keep HID I/O off every shared lock. Use bounded
channels between stream reader and writer threads; the in-flight frame is owned by the
writer until fully sent.

## Files and boundaries

## Acceptance

Unit tests for queue semantics/drop counting/cap; integration on ds-vdev: 32 fps × 60 s
push leaves `rev` unchanged and emits zero `/controls` events while `dropped` counts
replacements; `stream-stats` op returns the §6 stats shape.

## Verification

`cargo test -p ds-daemon frames::service`, integration run on ds-vdev, fixture gate,
workspace tests, conformance, check.sh, board validate — see metadata.

## Risks

Writer thread stall starving control — structural fix (separate threads, no shared
lock across I/O) plus the > 5 s watchdog that drops the in-flight frame and logs
(frame-service.md failure modes). Memory creep — enforce the 256 MiB cap in the
allocator path, test it.
