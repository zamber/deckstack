## Context

The stack is usable: CLI, MCP bridge (`ds-mcp`), Python client (`clients/ds-py`), packaged install
(DS-083), docs. What is missing is an onboarding route: an agent operator has no single page that
says "install this, start that, register this MCP server, and here is what you can do", and no
proof that a fresh agent can actually drive the deck. That gap is why integration is ad hoc.

## Goal

One documented path from zero to a working deck session for an agent, with an executable proof
and a maintenance rule so the page does not rot as the contracts and tools change.

## Scope

- `docs/agents.md`: prerequisites (udev, vendor app stopped), install (AppImage/tar from DS-083),
  daemon lifecycle, MCP server registration (Claude Code/Claude Desktop and one generic client),
  the full tool list with a one-line example each, the ds-py equivalents, a "what to do when a
  call fails" table (E_* codes and where to look), and a short "design constraints" section
  (argv-only exec, no raw HID escape, rev semantics).
- `examples/agents/mcp/`: a minimal MCP client config snippet and a 20-line script that lists
  tools and sets a key colour.
- `tests/conformance/agent-onboarding/run.py`: spawns ds-vdev + daemon + ds-mcp, performs the
  MCP handshake and the calls above, then the same through clients/ds-py; exit 0, cleanup.
- `AGENTS.md`: a pointer plus the upkeep rule ("when a contract, tool name or default changes,
  update docs/agents.md in the same commit").
- The page must state the alpha status and what is deliberately absent (web UI, plugins on PyPI
  yet, Windows/macOS).

## Out of scope

New protocol features; a hosted service; changing ds-mcp behaviour except where a tool name is
wrong (report it).

## Implementation notes

Read `docs/components/mcp-bridge.md`, `docs/contracts/cli.md`, `clients/ds-py/README.md`,
`docs/runbook.md`, and the DS-083 install layout. Keep the examples runnable against vdev.

## Files and boundaries

Only the paths in `touches`. `docs/reviews/` and `docs/discovery/` are protected.

## Acceptance

The scripted proof exits 0 and `docs/agents.md` covers install -> daemon -> MCP -> tools ->
troubleshooting without gaps.

## Verification

`python tests/conformance/agent-onboarding/run.py`, `python tests/conformance/run.py`,
`sh tools/check.sh`, board validate.

## Risks

MCP client registration differs per client; document exactly two and link the spec for others.
Avoid duplicating the tool list from the bridge docs: generate it or state that the bridge doc is
normative and keep a short table here.

## Definition of done

PR merged; an agent that has never seen the project can follow the page to a first successful
`deck_set`.

## Notes
