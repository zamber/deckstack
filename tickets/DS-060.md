## Context

Phase 6 (docs/60-roadmap.md): ds-focus closes OPEN O1. Component spec
docs/components/focus-sender.md (R4: the watcher is an ordinary external program; the
daemon contains no watcher, D17). Events land on the DS-040 bus as
`app/focus/changed`; bindings (DS-041/042) do the recoloring; DS-044 mirrors into
/focus atomically.

## Goal

A standalone `ds-focus` binary that watches window focus on Linux and emits
`app/focus/changed` events, with a deterministic `--inject` mode for conformance.

## Scope

- `bins/ds-focus/`: arg parsing, backend trait, KWin D-Bus backend (primary on
  Bazzite/KDE Wayland), wlr-foreign-toplevel backend, X11 fallback; 300 ms settle;
  emit via ds-client (one-shot `ds emit`-equivalent); `--inject file.ndjson` test mode;
  config under `/settings/senders/focus`.
- `tests/conformance/focus_sender.sh`: inject → `ds events --ndjson` / `ds watch
  app/focus --ndjson` assertions.
- `docs/components/focus-sender.md`: only gap fixes.

## Out of scope

The daemon-side mirror (DS-044), bindings (DS-041/042), MCP bridge (DS-061), Windows/
macOS focus backends (DS-072/073 — the trait keeps them additive), MPRIS/media.

## Implementation notes

Read docs/components/focus-sender.md, docs/contracts/actions.md §6 chain B,
docs/40-platforms.md §1 (focus row), docs/open-questions.md O1. Depends only on
ds-client — no daemon changes. The ≤ 500 ms end-to-end number needs a real DE session;
the vdev part (emit latency) is what CI checks.

## Files and boundaries

`new:tests/conformance/focus_sender.sh`. Do not edit `bins/ds/` (DS-016/032/041),
