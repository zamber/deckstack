# Ticket board — how to work in deckstack

All changes to this repo go through a ticket. The board is the set of `tickets/DS-*.md`
files plus the generated `tickets/BOARD.md`, `tickets/GRAPH.md`, and `tickets/index.json`
(regenerated by `python3 tools/tickets.py sync` — never edit them by hand).

Read first: `AGENTS.md`, `docs/AGENT-WORKFLOW.md` (long protocol), `docs/00-scope.md`
(normative scope), your ticket file. Commit format: `ticket(DS-XXX): …` with the
`Generated by Mistral Vibe.` + `Co-Authored-By: Mistral Vibe <vibe@mistral.ai>` trailer.

## State machine

```
backlog → ready → doing → review → done
   ↑        ↓        ↓        ↓
   └──── blocked ←─┴────────┘   (blocked always carries blocked_reason)
```

- `backlog` — not yet claimable (deps not done) or not yet triaged.
- `ready` — deps all `done`; claimable now. `sync` auto-promotes backlog → ready when
  every dep is done, so you usually never set `ready` by hand.
- `doing` — one worker owns it; has `owner`, `branch` = `ticket/<id>`,
  `worktree` = `.worktrees/<id>`, `pr` = `prs/<id>.md`.
- `review` — PR submitted; steward is reviewing.
- `done` — merged to `main`, acceptance green. Terminal.
- `blocked` — needs `blocked_reason`; can return to `ready`/`backlog`.

Only `depends_on` is authored by hand; `blocks` and the graph are computed. A ticket in
`ready`/`doing`/`review`/`done` must have all deps `done` — `validate` enforces it.

## How to pick work

```sh
python3 tools/tickets.py ready      # ready set + next-up (backlog whose deps are done)
python3 tools/tickets.py list --state ready --json
python3 tools/tickets.py graph      # DAG, critical path, lanes
```

Pick a `ready` ticket whose `touches` do not overlap the `touches` of any `doing`
ticket (`validate` fails on such collisions — check `python3 tools/tickets.py list
--state doing` first). Contracts (`schemas/`, `docs/contracts/`) are high-contention:
one ticket at a time. Prefer the smallest ready ticket in your lane.

## Claim → work → submit → review → merge

```sh
python3 tools/tickets.py claim DS-XXX --owner <your-name>   # ready -> doing
sh tools/wt.sh new DS-XXX --owner <your-name>               # worktree .worktrees/DS-XXX, branch ticket/DS-XXX
# ... edit only paths listed in the ticket's `touches` (new: = to be created) ...
git add -A && git commit -m "ticket(DS-XXX): …"              # heredoc + Vibe trailer
sh tools/pr.sh submit DS-XXX                                # writes prs/DS-XXX.md, pushes to `review`
# steward: sh tools/pr.sh review DS-XXX  (verdict into prs/DS-XXX.md)
# steward: sh tools/pr.sh merge DS-XXX   (merges to main, sets ticket done, removes worktree)
```

One ticket = one PR = one worktree. Never commit to `main` directly; never edit files
outside your ticket's `touches` (if scope must change, extend them through the tool first:
`python3 tools/tickets.py add-touch DS-XXX --add <path>` — never hand-edit the metadata
block).
`tools/wt.sh`, `tools/pr.sh`, `tools/setup-review-remote.sh`, and `prs/` land via DS-002.

## Recovery after a dead worker

```sh
python3 tools/tickets.py recover
```

lists every `doing`/`review` ticket with owner, whether the branch `ticket/<id>`, the
worktree `.worktrees/<id>`, and `prs/<id>.md` still exist, and the last commit on the
branch. If the worktree is gone but the branch exists, re-create it
(`git worktree add .worktrees/DS-XXX ticket/DS-XXX`) and continue, or
`python3 tools/tickets.py unclaim DS-XXX` to hand the ticket back. If the branch is
gone, the work is lost unless it was pushed to the `review` remote. The steward runs
`recover` at the start of every triage.

## File-collision rule

`touches` is the ownership list. Two `doing` tickets may not have overlapping `touches`
(prefix/glob overlap) — `validate` reports it as a `file collision` error. Before
claiming, compare your candidate's `touches` against all `doing` tickets; if they
overlap, sequence the tickets or split one. `new:` marks a path that does not exist yet.

## Roles

- **Worker** (coding agent): claims one ticket at a time, works in its worktree, opens
  one PR. Never merges, never commits to `main`.
- **Steward** (`agents/deckstack-steward.md`, DS-005): triages the ready set, claims/
  assigns, checks collisions, reviews PRs, runs acceptance, merges, updates the board,
  runs `recover`. Only role that merges to `main`.

## Sizes

- **S** — a day or less; one small file or a config; no design decisions.
- **M** — a few days; one crate/module or a script suite with tests.
- **L** — a week or more; a subsystem with contracts, tests, and docs.

## Board maintenance

```sh
python3 tools/tickets.py sync       # regenerate index.json/BOARD.md/GRAPH.md; auto-promote ready
python3 tools/tickets.py validate   # must print OK; CI gate via tools/check.sh (DS-003)
python3 tools/tickets.py add-touch DS-XXX --add <path> [--add …]   # extend touches when scope must change (lock + validate + sync; refuses duplicates, invalid entries, doing-ticket collisions)
python3 tools/tickets.py state DS-XXX <state> [--owner …] [--reason …]
python3 tools/tickets.py show DS-XXX
```

New tickets: copy `tickets/TEMPLATE.md`, fill the metadata block and all body sections,
run `sync` then `validate`. Never hand-edit BOARD.md/GRAPH.md/index.json.
