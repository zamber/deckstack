## Context

Phase 3 needs the virtual device to reproduce device-side slowness so backpressure is
testable in CI without hardware. docs/30-testing.md §2 already specifies
`--throttle-kbps` (simulates ~2.1 MB/s) and `--drop-after` (hot-unplug) on ds-vdev;
DS-017 landed the base knobs. ipc.md §5: producers must respect `stream-credit`
budgets; excess → `stream-nack` + `E_LIMIT`. streaming.md §3: the in-flight frame is
never dropped mid-send.

## Goal

Deterministic vdev throttle/drop knobs plus tests proving the daemon and CLI behave
correctly under backpressure: credits respected, drops counted, in-flight frames whole,
control plane unaffected.

## Scope

- `crates/ds-vdev/src/throttle.rs`: implement/harden `--throttle-kbps` (per-write
  delay pacing to the requested bandwidth) and `--drop-after N` (stop accepting after
  N writes = unplug), plus ds-vdevctl visibility of throttle state.
- `tests/bench/backpressure.rs`: 32 fps push against throttled vdev; assert
  `dropped == sent - accepted`, in-flight frame reassembles to its full sha, control
  `get` p99 ≤ 10 ms.
- `docs/components/virtual-device.md`: document the knobs and their exact semantics.

## Out of scope

Frame service policy (DS-031), encoder (DS-030), CLI (DS-032), streaming bench budgets
(DS-033), real-device hot-plug behavior (DS-023).

## Implementation notes

Read docs/30-testing.md §2/§5, docs/contracts/streaming.md §3, docs/components/
virtual-device.md. Keep vdev deterministic by default — throttle only when asked
(DS-017 note). If real hardware and vdev disagree on pacing, fix vdev first
(escalation rule).

## Files and boundaries

Only `touches`: `new:crates/ds-vdev/src/throttle.rs`, `new:tests/bench/backpressure.rs`,
`docs/components/virtual-device.md`. Do not edit other ds-vdev files owned by DS-017
unless strictly additive, and never `crates/ds-daemon/`.

## Acceptance

Backpressure bench green; scripted smoke shows `E_LIMIT`/exit 5 path on credit
exhaustion and an intact in-flight frame; throttle knobs documented.

## Verification

cargo tests for ds-vdev, the backpressure bench, smoke, fixture gate, workspace
tests, conformance, check.sh, board validate — see metadata.

## Risks

Throttle math off → benches mis-measure; validate throttle-kbps against wall-clock
bytes/sec in the unit test. Flakiness — deterministic delays, no random drops unless
`--drop-after` is set.

## Definition of done

reuse the knobs.
