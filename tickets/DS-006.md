## Context

Agent steering is first-class in alpha (docs/00-scope.md: AGENTS.md,
docs/AGENT-WORKFLOW.md, skills/deckstack/SKILL.md, and the CLI self-description
contract in docs/contracts/cli.md). Docs that lie about commands are worse than no
docs — this ticket validates them against reality after the tooling exists.

## Goal

Make AGENTS.md, docs/AGENT-WORKFLOW.md, README.md, PLAN.md, and skills/deckstack/SKILL.md
operationally truthful: every command they show works today or is explicitly marked as
landing with a named ticket, and the agent-facing CLI contract is stated.

## Scope

- Execute each command in AGENTS.md (read order aside): `sh packaging/bootstrap.sh`,
  `sh tests/fixtures/validate.sh`, `cargo test --workspace` (once DS-004 lands),
  `python tests/conformance/run.py` (once DS-018 lands), `python3 tools/tickets.py
  sync|validate|ready|graph`, `ds daemon start --device virtual:/tmp/vdev.sock`
  (once DS-015/DS-017 land — until then mark "lands with DS-015/DS-017").
- Reconcile docs/AGENT-WORKFLOW.md "intended commands" with the real tools/wt.sh /
  tools/pr.sh from DS-002 and the steward from DS-005; replace intended with actual.
- Update README.md and PLAN.md quick-start so they point at the ticket flow and carry
  no stale claims (no migrate, no web UI, Linux-only, empty state).
- Update skills/deckstack/SKILL.md with the real commands and the ticket lifecycle.
- State the CLI self-description contract (docs/contracts/cli.md: `ds schema`,
  `ds describe`, `--help` everywhere, stable exit codes 0-8, `--json`/`--ndjson`) as
  what agents rely on — implementation is DS-016/DS-062.

## Out of scope

Implementing the CLI or daemon (DS-015/DS-016/DS-062); changing the workflow protocol
itself; editing BRIEF.md, docs/discovery/, docs/reviews/.

## Implementation notes

Read order: AGENTS.md → docs/00-scope.md → PLAN.md → docs/contracts/ →
docs/AGENT-WORKFLOW.md → tickets/README.md. For each command, run it; if the artifact
it needs does not exist yet, the doc must say "lands with DS-0XX" instead of showing a
dead command. Keep the report shape and commit format sections in AGENTS.md exact.

## Files and boundaries

Only the `touches` list. Contracts (docs/contracts/, schemas/) are owned by phase 1
tickets — reference them, do not edit.

## Acceptance

A fresh agent following only AGENTS.md + skills/deckstack/SKILL.md can clone, bootstrap,
validate, find ready work, claim, and open a PR — every command either works or names
the ticket that delivers it.

## Verification

`python3 tools/tickets.py validate`; `sh tools/check.sh`; paste the executed commands
and outputs into prs/DS-006.md.

## Risks

Docs drift again as phase 1 lands — mitigate by re-running this validation at each
phase boundary (note it in tickets/README.md maintenance section).

## Definition of done

PR merged; all steering commands verified or ticket-referenced; no stale
migration/web-UI/platform claims anywhere in the touched files.

## Notes

Depends on DS-001 (done) and DS-005 (steward role) — stays backlog until DS-005 is
done; `sync` will promote it automatically.
