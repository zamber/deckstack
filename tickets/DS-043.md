## Context

Phase 4 exec enforcement — "enforced, not asserted" (S3, reconciles review M1/M2).
Contract: docs/contracts/actions.md §4; threat T5 in docs/20-security.md §2; policy
surface `/policy` in schemas/state.json (S13: no policy exists only in prose). The
rejected patterns are `shell=True` (`hubdeck/.../platforms/posix.py:70`) and
`{python: …}` exec. Step plumbing is DS-042.

## Goal

A policy module that makes shell/interpreter execution impossible through bindings
while allowing explicitly allowlisted absolute binaries, fully audited.

## Scope

- `crates/ds-daemon/src/policy/`: `/policy/exec/allow` − `/policy/exec/deny` evaluation
  (deny wins), admin-scope + `allow_exec` check, cwd confinement to
  `/policy/fs/roots` + `/tmp`, spawn via execve with rlimits (RLIMIT_CPU 10 s,
  NPROC 64, NOFILE 64, AS 1 GiB), scrubbed env `{PATH, HOME, LANG}` (no token),
  process-group kill on daemon exit.
- Audit: log line + `deck/system/exec {argv, pid, rev}` event per spawn.
- `schemas/state.json`: only if the `/policy` subtree needs a field adjustment — the
  fields exist (S13); prefer conforming. `docs/20-security.md`: mapping updates only.
- Conformance under `tests/conformance/exec/` incl. the T5 cases above and a positive
  case (allowlisted `/bin/true` or a test fixture binary).

## Out of scope

Step vocabulary (DS-042), bindings CRUD (DS-041), plugin sandbox rlimits (DS-050 has
its own), security conformance mapping T1-T12 (DS-081), fuzzing (DS-080).

## Implementation notes

Read docs/contracts/actions.md §4, docs/20-security.md T5/§4-5, schemas/state.json
/policy, schemas/binding.json (prefixItems). There is NO timeout_ms in the schema —
runaway processes die by RLIMIT_CPU (S11/m5). Deny-list check happens before spawn;
constant-time token compare is DS-012's concern, not here.

## Files and boundaries

Only `touches`: `new:crates/ds-daemon/src/policy/`, `schemas/state.json` (minimal),
`docs/20-security.md` (mapping only), `new:tests/conformance/exec/`. Do not edit
router files (DS-040/042/044) — expose a `policy::check_exec(...) -> Result<(), E_*>`
API the router calls.

## Acceptance

All T5 conformance cases green: `/bin/sh -c` → E_CAP + no file; relative argv[0] →
E_SCHEMA; `/usr/bin/env` → E_CAP; allowlisted binary executes fire-and-forget with
`deck/system/exec` emitted; rlimit kill of a CPU hog verified (spawn a fixture spinner,
expect SIGKILL by CPU limit within ~11 s).

## Verification

cargo tests, conformance -k exec, fixture gate, workspace tests, conformance,
check.sh, board validate — see metadata.

## Risks

Deny-list gaps (new interpreter paths) — the allowlist is the primary control, deny is
defense in depth; document that admins extend both via /policy. Fire-and-forget pid
reaping — reap children to avoid zombies.

## Definition of done

PR merged; T5 machine-checked on vdev; DS-081 can map it; phase 5 depends on this.

local, no protection against the user themselves (docs/20-security.md §6).
