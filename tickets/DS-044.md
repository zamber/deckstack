## Context

S7 (actions.md §2, event-router.md): the router must mirror the `app/focus/changed`
payload into `/focus` in the SAME transaction that dispatches bindings, so `/focus`-based
`when` conditions are never stale. `/focus` schema exists in schemas/state.json
({app, title, pid, at_rev}). Chain B in actions.md §6 is the conformance scenario;
ds-focus (DS-060) is the producer, `ds emit` works today.

## Goal

Atomic focus ingest: `/focus` update and binding dispatch commit together, proven by
conformance — this is what makes the focus→recolor chain correct.

## Scope

- `router/ingest.rs`: special-case ingest for `app/focus/changed` (and any
  `app/<sender>/<topic>` mapped to a state mirror — only focus today): build one
  transaction {set /focus …, apply binding effects} and commit atomically; set
  `at_rev` to the committing rev.
- Conformance under `tests/conformance/focus_ingest/`: chain-B shape — emit focus event
  with a binding on `when {path: /focus/app, op: eq, value: code}` doing a set; assert
  the set happened and `/focus` read-back shows the same rev family; also the payload-
  based `when` variant fires in the same dispatch.
- If the exact rollback semantics need pinning, edit docs/contracts/actions.md in the
  same commit as any schema/behavior change.

## Out of scope

The bus (DS-040), bindings storage (DS-041), step execution (DS-042), ds-focus itself
(DS-060), latency bench (DS-045).

## Implementation notes

Read docs/contracts/actions.md §2/§6, docs/components/event-router.md (atomic event
ingest S7), schemas/state.json /focus. Implement inside the ds-state transaction API
(DS-011) — one commit, one rev. Do not implement ingest as "set then dispatch"
(two transactions) — that is the bug S7 fixes.

## Files and boundaries

Only `touches`: `new:crates/ds-daemon/src/router/ingest.rs`,
`new:tests/conformance/focus_ingest/`. Do not edit `router/mod.rs`/`bus.rs` (DS-040),
`router/steps.rs` (DS-042), schemas (already shaped).
