## Context

Phase 5 (docs/60-roadmap.md): plugin host. Contract: docs/contracts/plugins.md §1-5;
manifest schema schemas/plugin-manifest.json; component docs/components/plugin-host.md;
design ADR-006, D08. Threats T3/T11 in docs/20-security.md. Router `plugin` steps (DS-042)
call into this host; exec policy (DS-043) is the sibling for `exec` steps.

## Goal

A daemon module that runs plugins as isolated processes with the contractual wire
protocol, capability enforcement, resource limits, watchdog, and clean lifecycle.

## Scope

- `crates/ds-daemon/src/plugins/`: supervisor (spawn from plugin dir, pipes, env
  `{PATH, HOME, LANG, DS_PLUGIN_TOKEN}`, process group), wire protocol (hello/register/
  event/invoke/effects/request/reply), manifest validation, cap enforcement per
  request/effect, effect application via ds-state transactions, `/plugins/<id>` state
  {manifest, status, state, stats}, host-mediated net (`request kind:"net"` — host
  matches against plugin `net:<glob>` AND /policy/net/allow_hosts, glob = `*` matches
  exactly one DNS label anchored; daemon resolves DNS and connects itself, T11/S4),
  watchdog (2 s invoke timeout -> degraded; respawn ≤ 3/10 min), kill-on-exit.
- `ds plugin list|invoke <id.action> [args]|install <dir>|remove <id>|logs <id>` verbs
  (cli.md §1) — CLI side lives in bins/ds but coordinate; this ticket owns the host and
  may add the verb files if DS-016's CLI is done.
- `schemas/plugin-manifest.json` + `docs/contracts/plugins.md`: only minimal edits if a
  real gap is found, schema and contract in the same commit.

## Out of scope

SDKs (DS-051/052), abuse tests (DS-053), example plugin (DS-054), router integration
beyond the DS-042 seam, net policy admin (DS-043's /policy surface).

## Implementation notes

Read docs/contracts/plugins.md (all sections), docs/components/plugin-host.md,
schemas/plugin-manifest.json, docs/20-security.md §2 T3/T11/§4. Rejected patterns:
in-process plugins, declared-only permissions. Landlock ABI>=4 net-deny where
available is defense in depth; host mediation is the control (documented gap where ABI
< 4).

## Files and boundaries

Only `touches`: `new:crates/ds-daemon/src/plugins/`, `schemas/plugin-manifest.json`,
`docs/contracts/plugins.md`, `docs/components/plugin-host.md` (plus new CLI verb files
under bins/ds only if needed). Do not edit `crates/ds-plugin-sdk/` (DS-051),
`plugins-py/` (DS-052), router files.

## Acceptance

A test plugin process (built in the ticket's tests, or the DS-054 example) installs,
registers, receives an injected event, returns effects that land in state; cap
violation → E_CAP counted; crash → watchdog respawn; daemon stop leaves no plugin
processes.

## Verification

cargo tests, conformance -k plugins, fixture gate, workspace tests, conformance,
check.sh, board validate — see metadata.

## Risks

Landlock availability variance — feature-detect ABI, degrade to wrapper checks, record
gap. Zombie processes — reap children. Effect storms — cap effects per invoke (e.g.
100) and count violations.

through it.
