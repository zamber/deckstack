## Context

Cross-cutting verification: docs/30-testing.md §5 defines bench budgets and §8 the CI
matrix (Linux-only alpha; hardware job on self-hosted Bazzite). DS-003 landed the CI
skeleton; DS-020/033/045 built the benches. This ticket wires budgets as CI gates on
vdev.

## Goal

Performance regressions fail CI automatically on Linux/vdev — the budgets are gates,
not reports.

## Scope

- `.github/workflows/ci.yml`: add the bench job/step per acceptance; artifacts;
  concurrency guards so benches don't run on loaded shared runners misleadingly
  (or use the self-hosted runner for benches — decide and document).
- `crates/ds-bench/`: add `--quick` mode + machine-readable JSON output consumed by CI
  for budget checks (exit nonzero beyond budget).
- `tools/check.sh` — wait, check.sh is DS-003's file; coordinate: this ticket may add
  a `bench --quick` invocation only if DS-003's check.sh already has a hook point;
  otherwise keep check.sh untouched and document the CI-only gate (note in PR).
- `docs/30-testing.md`: exact commands + artifact names.

## Out of scope

The benches themselves (DS-020/033/045), hardware perf claims, DS-083 release
packaging, changing budgets (steward decision).

## Implementation notes

Read docs/30-testing.md §5/§8, .github/workflows/ci.yml (from DS-003), docs/60-
roadmap.md exit criteria. Budgets must have CI headroom (shared runners) — document the
margin policy. Never let a bench job block merges flakily: one retry with a recorded
flake note is acceptable per AGENT-WORKFLOW escalation, or use the self-hosted runner.

## Files and boundaries

Only `touches`: additions inside `new:crates/ds-bench/` (quick mode/JSON output —
coordinate with DS-033's files; non-overlapping new files), `new:.github/workflows/
ci.yml` (DS-003's file — append a job, minimal diff; if DS-003 hasn't landed it,
create via new: and note the coordination), `docs/30-testing.md`. Avoid editing
ds-bench files owned by DS-033 — add new files (e.g. `src/bin/ci_gate.rs`).

## Acceptance

CI YAML valid and contains the bench gate; `cargo bench -p ds-bench -- --quick`
works locally; docs updated; a deliberately over-budget local run (throttled harder)
fails the gate (evidence in PR).

## Verification

check.sh, CI YAML validation, fixture gate, workspace tests, conformance, board
validate — see metadata.

## Risks

Flaky perf gates blocking merges — margin policy + self-hosted runner for benches;
flakes recorded. check.sh runtime creep — quick mode keeps local fast.

## Definition of done

PR merged; bench budgets enforced in CI on vdev; DS-083 release can cite green gates.
