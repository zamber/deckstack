## Context

Phase 3 (docs/60-roadmap.md) starts with the wire/device encode path.
docs/contracts/streaming.md §2 is normative: the device accepts **baseline JPEG only,
standard Huffman tables, 4:4:4** — optimized-Huffman input is rejected with `E_FORMAT`
(`upstream/PROTOCOL.md:87-96`). Chunking is `02 <cmd> <chunk u16 LE> <len u16 LE>
<index> <last> <≤312 B>` inside 320 B reports. Component spec:
docs/components/frame-service.md. The DSF1 stream socket lands in DS-013; DS-020 gives
the end-to-end vdev path with golden sha assertions to build on.

## Goal

A daemon-side encode+chunk module that turns any accepted wire frame into the exact
device wire format, with golden sha256 fixtures under `tests/golden/` proving the
bytes on the (virtual) wire.

## Scope

- `crates/ds-daemon/src/frames/encode.rs`: wire-frame validation (≤ 16 MB payload,
  decode caps ≤ 4096×4096, ≤ 300 frames, ≤ 30 fps, min frame 0.02 s) and re-encode to
  baseline JPEG / standard Huffman / 4:4:4 using the `jpeg-encoder` crate (pinned
  version); quality per target: `keys` q80, `key:N` q90, `dial` q85. Reject
  optimized-Huffman/progressive input with `E_FORMAT`.
- `crates/ds-daemon/src/frames/chunk.rs`: chunked report builder for cmds `02 35`
  (keys/panel), `02 36` (key:N), `02 45` (dial), ≤ 312 B payload per 320 B report,
  index/last flags per `schemas/stream-frame.json` and the report codec from DS-014.
- `schemas/stream-frame.json`: only if the meta needs a new field; update
  `docs/contracts/streaming.md` in the same commit if so (contracts are normative).
- `tests/golden/`: golden sha256 fixtures per target produced once on ds-vdev
  (never shipped as deck defaults — test fixtures only, empty-state invariant holds).

## Out of scope

Queue/writer/telemetry service (DS-031), `ds stream` CLI (DS-032), bench (DS-033),
animation/GIF pipeline (DS-034), vdev throttling (DS-035), real hardware (phase 2).

## Implementation notes

Read docs/contracts/streaming.md §2/§8, docs/components/frame-service.md,
schemas/stream-frame.json, and the DS-014 report codec. Encode must be deterministic
for golden shas: pin the `jpeg-encoder` version in Cargo.toml and record the version
in the golden fixture header. Test through ds-vdev reassembly (DS-017/DS-020 helpers),
not by mocking the device.

## Files and boundaries

Only `touches`: the two new frame-module files, `schemas/stream-frame.json` (with
matching contract edit if changed), `new:tests/golden/`. Do not edit
`crates/ds-daemon/src/frames/service.rs` (DS-031's file) or `crates/ds-vdev/`
(DS-017/DS-035).

## Acceptance

Unit tests green for every target size and every rejection case; a scripted raw-DSF1
push of a PNG to `stream.sock` on ds-vdev yields `ds-vdevctl frames keys` sha256 equal
to `tests/golden/keys.sha256`; an optimized-Huffman JPEG gets `E_FORMAT` and is not
forwarded.

## Verification

`cargo test -p ds-daemon` (frames modules), the scripted ds-vdev sha check, fixture
gate, workspace tests, conformance, check.sh, board validate — see metadata.

## Risks

Golden sha drift across encoder/dependency versions — pin versions and regenerate
goldens deliberately (never silently). Wire-vs-device format mismatch — assert the
reassembled vdev frame is baseline 4:4:4 by decoding it in the test.

## Definition of done
