## Context

Every PR needs the same gate (docs/AGENT-WORKFLOW.md §Verification): schema/fixture
validation, ticket board validation, and — once the workspace exists (DS-004) —
cargo fmt/clippy/test, and once the conformance runner exists (DS-018) — the
conformance suite. CI must be Linux-only for alpha (docs/00-scope.md invariant 4).

## Goal

Provide `tools/check.sh` (the single local gate that pr.sh review/merge also runs),
make `packaging/bootstrap.sh` the one-command dev setup, and add a Linux-only CI
skeleton that runs the gate on push/PR.

## Scope

- `tools/check.sh`: always run `sh tests/fixtures/validate.sh` (must print ALL CHECKS
  PASSED) and `python3 tools/tickets.py validate`; if `Cargo.toml` exists, run
  `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`, `cargo test
  --workspace`; if `tests/conformance/run.py` exists, run it with the venv python if
  present else `python3`. Print a clear summary; exit nonzero on any failure.
- `packaging/bootstrap.sh`: create `.venv`, install `tests/requirements.txt`, then run
  `tools/check.sh` (and `cargo build --workspace` when the workspace exists). Must work
  on a fresh clone.
- `.github/workflows/ci.yml`: Linux only, on push + pull_request, single job running
  `sh tools/check.sh` (plus fixture gate), with Rust and Python preinstalled via
  actions. No Windows/macOS jobs in alpha.

## Out of scope

Cargo workspace itself (DS-004), conformance runner (DS-018), hardware jobs (phase 2).
No changes to tests/fixtures/validate.sh behaviour beyond keeping it green.

## Implementation notes

Read docs/30-testing.md §8 (CI matrix) and docs/AGENT-WORKFLOW.md §Verification.
check.sh must degrade gracefully while Cargo.toml / tests/conformance/run.py do not
exist yet (skip those steps with a printed note), so it is green from phase 0 onward.

## Files and boundaries

Only the `touches` list. Protected: BRIEF.md, docs/discovery/, docs/reviews/.

## Acceptance

On a clean main after DS-004 lands, `sh tools/check.sh` exits 0 and runs cargo
fmt/clippy/test; before that it exits 0 having run the fixture + ticket gates;
`sh packaging/bootstrap.sh` exits 0 on a fresh clone.

## Verification

`sh tests/fixtures/validate.sh` → ALL CHECKS PASSED; `sh tools/check.sh` exit 0;
`python3 tools/tickets.py validate` exit 0; workflow file parses (yamllint or GitHub
syntax check).

## Risks

check.sh must not fail merely because later-phase artifacts are absent — gate each
optional step on file existence.

## Definition of done

PR merged; `sh tools/check.sh` and `sh packaging/bootstrap.sh` both green locally;
CI skeleton committed.

## Notes
