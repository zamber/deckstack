## Context

Phase 3 animation path. Limits are contractual: animation ≤ 300 frames @ ≤ 30 fps,
min frame 0.02 s, wire frame ≤ 16 MB, decode ≤ 4096×4096 (docs/contracts/streaming.md
§2/§5; precedents `hubdeck/.../render/images.py:21-23`, `control.py:36`).
`ds stream push dial --file anim.gif --loop` is a cli.md §4 example. Encode/chunk is
DS-030; the CLI verb is DS-032.

## Goal

Multi-frame input (GIF files, `--dir` sequences) decoded, limited, and streamed frame
by frame through the DS-031 service, with the limits enforced and tested.

## Scope

- `crates/ds-daemon/src/frames/animate.rs`: GIF decode (frames, delays, loop count),
  frame-count/fps/duration validation, mapping onto the DSF1 meta (`frames`, `fps`,
  `loop`) and per-frame seq/ts_ms; rejection paths `E_FORMAT` (undecodable/over
  decode caps) and `E_LIMIT` (over 300 frames / over 30 fps / under 0.02 s).
- Conformance cases under `tests/conformance/streaming/` driving the real `ds` binary
  on ds-vdev: valid animation, each limit boundary, GIF --loop on dial, per-frame
  vdev sha log via `ds-vdevctl writes`.
- No schema change expected (limits already in stream-frame.json); if one is needed,
  change `schemas/stream-frame.json` + `docs/contracts/streaming.md` in the same commit.

## Out of scope

Single-frame encode (DS-030), queue service (DS-031), CLI parsing (DS-032), bench
(DS-033), vdev throttle (DS-035). Video decode stays external (ffmpeg, R4) — the CLI
only consumes directories of stills.

## Implementation notes

Read docs/contracts/streaming.md §2/§5/§7, schemas/stream-frame.json, cli.md §4.
GIF delay→fps conversion: fps = clamp(round(1000/delay_ms), ≤ 30); drop frames shorter
than 20 ms by merging delays rather than emitting sub-0.02 s frames. Keep decode
memory-bounded (decode one frame at a time, ≤ 4096×4096).

## Files and boundaries

Only `touches`: `new:crates/ds-daemon/src/frames/animate.rs`,
`new:tests/conformance/streaming/`. Do not edit `encode.rs`/`chunk.rs`/`service.rs`
(DS-030/DS-031), `bins/ds/` (DS-032).

## Acceptance

Conformance streaming cases green on vdev: boundaries enforced, loop honored, S1
invariant holds during animation (rev delta 0 — assert in the case).

## Verification

cargo tests, `python tests/conformance/run.py -k streaming`, fixture gate, workspace
tests, check.sh, board validate — see metadata.

## Risks

GIF variants (interlaced, local palettes, huge frame counts) — fuzz lightly with a few
fixture GIFs; oversized GIFs must hit the 16 MB wire cap before decode.
