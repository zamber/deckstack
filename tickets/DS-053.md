## Context

Phase 5 failure isolation (plugins.md §5, plugin-host.md failure modes) and the
security test cases T3/T5/T6/T11 in docs/20-security.md §2. The host (DS-050) and the
Python wrapper (DS-052) exist by now; abuse plugins are written with ds-plugin-py (or
raw stdio) inside the test suite.

## Goal

Machine-checked proof that a malicious or buggy plugin cannot take down the daemon,
escape its capabilities, or reach non-granted hosts — the phase-5 exit "abuse tests
pass".

## Scope

- `tests/conformance/plugins/`: abuse cases — fork bomb, AS memory hog, cap violation,
  fs traversal (`../../etc/shadow`-style request), oversized net URL, net glob edge
  matrix vs a fake HTTP server, invoke timeout → degraded → restart, crash/respawn.
- After each case: assert daemon alive (ping/get), violation counters incremented,
  no state corruption.
- `docs/20-security.md`: update the T3/T5/T6/T11 "Test" column to point at the exact
  conformance case paths (docs-only edit, same commit discipline).

## Out of scope

The host enforcement itself (DS-050), exec policy (DS-043), fuzz/limits (DS-080),
security mapping T1-T12 (DS-081), lights.lan plugin (DS-070).
