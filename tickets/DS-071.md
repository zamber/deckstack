## Context

Post-alpha, ticket-driven porting (docs/70-porting-notes.md, owner steering delta 2:
no export/import/migrate, no compat layer; the old app is never a runtime dependency —
one HID owner). The Salon deck's live config uses `plugins.huemux.url:
http://lights.lan` and `presets.default.extends: [salon-pages, salon-controls]` — the
candidate list starts there. Depends on bindings (DS-041) and the lights plugin
(DS-070).

## Goal

A reviewed porting inventory (port/drop per behaviour, with evidence) plus one real
button ported end to end as the template for future porting tickets.

## Scope

- `docs/porting/inventory.md`: every candidate behaviour from docs/discovery/ with
  `path:line` evidence, port/drop decision + reason, and the ticket shape it would get.
- One port: a Salon key (e.g. a lights toggle) as `ds bind …` + `ds plugin invoke
  lights.set …`, with conformance acceptance on vdev per docs/70-porting-notes.md §3.
- `docs/70-porting-notes.md`: link the inventory (minimal edit).

## Out of scope

Bulk porting (each behaviour gets its own ticket later), any importer/exporter (never),
changes to core or contracts, lights plugin implementation itself (DS-070).

## Implementation notes

Read docs/70-porting-notes.md, docs/80-integrations.md, docs/discovery/ (evidence
source — read-only), docs/contracts/actions.md. The ported button must work through
the public CLI only — that is the point of the exercise.

## Files and boundaries

Only `touches`: `new:docs/porting/`, `docs/70-porting-notes.md` (link edit). Do not
edit docs/discovery/ or docs/reviews/ (protected), schemas, or crates. If the port
needs a conformance case, put it under the owning phase's test dir via a new small
ticket — do not edit DS-045's files.

## Acceptance

Inventory reviewed (steward sign-off in the PR); the one ported button demonstrably
works on vdev with commands + output in prs/DS-071.md.

## Verification

Port acceptance run, fixture gate, conformance, check.sh, board validate — see
metadata.

## Risks

Inventory becoming a wishlist — every row needs evidence + a decision, not enthusiasm.
Old-config scraping temptation — explicitly out of scope; IDs come from user/agent
created state.

## Definition of done

PR merged; inventory is the single source for future porting tickets; one button
proven.

## Notes

Stays backlog until DS-070 (lights) and bindings are done.
