## Context

The CLI is a stateless Rust binary doing one read/mutate per invocation over the control
socket, sharing ds-client (ADR-002). It is self-describing — `ds schema`, `ds describe`,
`--help` everywhere, stable exit codes, `--json`/`--ndjson` — because agents discover
every capability from the CLI alone (R1/R10, docs/contracts/cli.md).

## Goal

The `ds` binary implements the phase-1 verb set with the full output/exit-code
contract, so the PLAN.md walking skeleton demo runs.

## Scope

- `bins/ds/` thin main over `crates/ds-client` (ds-client lands with DS-012/DS-015).
- Verbs (phase 1): `get`, `set` (incl. `--file` for images), `watch` (`--json` exit 1,
  `--ndjson` streams), `schema <name>`, `describe <path>`, `daemon start|stop|status`,
  `status`. Plus global `--help` at every level.
- Output: `--json` one object; errors actionable (`ds: path not found: … [exit 2]`);
  exit codes 0-8 per docs/contracts/cli.md; no `migrate` verb (must exit 1).
- Tests: unit tests for arg parsing/output shaping; integration smoke script driving a
  daemon on vdev.

## Out of scope

bind/unbind/emit/plugin/stream verbs (phases 3-5), ds-focus/ds-mcp (phase 6), WS/HTTP
adapter.

## Implementation notes

Read docs/contracts/cli.md and docs/components/cli.md (normative), PLAN.md §First
walking skeleton for the demo steps. Keep the CLI stateless: every invocation connects,
does one op, prints, exits. Self-description conformance tests land fully in DS-062;
here implement the contract.

## Files and boundaries

Only `touches`: `bins/ds/`, `docs/contracts/cli.md` (only if a clarification is
strictly needed — prefer conforming), `docs/components/cli.md`.

## Acceptance

Walking skeleton demo: `ds set /controls/keys/0/color '#3cc86e'` then `ds get
/controls/keys/0 --json` round-trips; `ds set /controls/keys/0/image --file …` →
golden sha via ds-vdevctl (with DS-017); `ds watch --ndjson` streams; `ds watch --json`
exits 1; `ds migrate` exits 1; every verb has `--help`.

## Verification

`cargo test --workspace`; scripted smoke in prs/DS-016.md output; `sh tools/check.sh`;
board validate.

## Risks

Exit-code drift — pin them in tests from day one (DS-062 deepens this).

## Definition of done
