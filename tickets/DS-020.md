## Context

Phase 1 exit (docs/60-roadmap.md, PLAN.md): the walking skeleton demo must be
observable — one key image pushed through the daemon reaches ds-vdev with a golden
sha256; control ops round-trip with rev; streaming/limits behave; `ds migrate` exits 1;
query p99 ≤ 10 ms under load. This ticket integrates DS-015/016/017/018 into that proof.

## Goal

A repeatable e2e script + bench skeleton under `tests/e2e/` that proves the phase-1
exit criteria, plus `examples/key.png` (a tiny test image — test fixture, never
installed as a default; empty-state invariant still holds for real users).

## Scope

- `tests/e2e/`: script that boots ds-vdev + daemon on tmp paths, runs the demo
  commands, asserts golden sha via ds-vdevctl, asserts rev/watch/migrate behaviours,
  runs a simple query-under-load loop and reports p99.
- `examples/key.png`: small valid PNG used by the demo (lives under examples/, not
  shipped as a deck default).
- Bench skeleton: looped `ds get` while a background setter runs; record p99; wire into
  check.sh via the conformance/e2e hooks (DS-082 formalises gates later).

## Out of scope

32 fps streaming bench (DS-033, phase 3), hardware smoke (DS-026), camera checks
(DS-027/028).

## Implementation notes

Read PLAN.md §First walking skeleton and docs/60-roadmap.md phase 1 exit. Reuse
tests/conformance/run.py process management — factor shared helpers into
tests/conformance and import, do not duplicate. The e2e must be deterministic and
leave no processes/files behind.

## Files and boundaries

Only `touches`: `tests/e2e/`, `examples/`.

## Acceptance

`tests/e2e` exit 0 with all assertions green on a fresh clone after `sh
packaging/bootstrap.sh`; outputs pasted into prs/DS-020.md.

## Verification

Full gate: fixture validate.sh, cargo test, conformance, e2e, check.sh, board validate.

## Risks

observations in the PR record instead of retry-looping (escalation rule).
