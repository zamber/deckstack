## Context

Pixel-level claims on hardware need a camera oracle (ADR-015, docs/90-verification.md).
deckstack-verify lives in-tree at `tools/verify/` during alpha and splits to its own
repo post-alpha (docs/50-repo-topology.md §0, repos.toml).

## Goal

A working camera harness: discover the camera, calibrate against the deck, capture the
live panel, compare pixels to the expected state, exposed as a `deckstack-verify`
CLI.

## Scope

- `tools/verify/` Python package + CLI: `discover`, `calibrate`, `capture`,
  `compare`, `check <target>` subcommands per docs/90-verification.md.
- Compare logic: capture → crop per calibrated target region → compare to expected
  image (from state) with a documented tolerance; report mismatches with saved
  artifacts.
- Self-test that runs against ds-vdev (virtual frames) so CI can exercise the pipeline
  without a camera; real camera runs are hardware-gated.
- Keep it subtree-splittable (clean package root at tools/verify/).

## Out of scope

Golden image sets (DS-028), integration into CI beyond the vdev self-test, repo split
(post-alpha).

## Implementation notes

Read docs/90-verification.md fully — it is the normative spec (discovery, calibration
procedure, capture, compare). Use stdlib + requirements already in
tests/requirements.txt where possible; add camera deps (e.g. OpenCV) to a
verify-specific requirements to keep the core venv lean.

## Files and boundaries

Only `touches`: `tools/verify/`, `docs/90-verification.md` (only if the harness needs
a clarification; prefer conforming).

## Acceptance

`deckstack-verify check key:0` and panel pass on the real deck with camera; vdev
self-test green in CI.

## Verification

vdev self-test; hardware check output in PR record; check.sh; board validate.

## Risks

Camera calibration drift — keep calibration artifacts versioned under
tools/verify/golden (DS-028).

## Definition of done

PR merged; camera-verified pixels demonstrated for key:0 and panel.
