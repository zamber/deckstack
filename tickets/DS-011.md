## Context

State is one JSON document, path-addressed, revision-stamped, starting empty (ADR-004,
docs/contracts/state.md, schemas/state.json). The two-plane rule (S1) is load-bearing:
frames and telemetry never enter the durable document or bump rev. Empty state at start
is a scope invariant (ADR-013) asserted by conformance later (DS-018).

## Goal

A `ds-state` crate that owns the state document: schema-validated load/save, path
get/set, transactions, rev, subscriptions, and the durable/telemetry split.

## Scope

- `crates/ds-state`: load from disk (or empty default), validate against
  `schemas/state.json` on every load and every mutation (use a JSON Schema validator;
  keep the dependency set small).
- Path addressing (`/controls/keys/0/color`), set/get/delete ops, each durable op
  bumping `rev` transactionally; multi-op transactions atomic (all-or-nothing).
- Subscriptions: watchers notified on durable path changes with the new rev.
- Telemetry split: `/telemetry/*` values held separately, never persisted, never bump
  rev; `get /telemetry/...` returns current sample without rev.
- Unit tests under `crates/ds-state/tests/` and `tests/state/`: empty-start invariant,
  rev semantics, transaction rollback, schema rejection of bad documents.
- Schema changes, if any, must land in the same commit as the code (contracts are
  normative) and keep `sh tests/fixtures/validate.sh` green.

## Out of scope

IPC transport (DS-012/013), daemon wiring (DS-015), CLI (DS-016), frames.

## Implementation notes

Read docs/contracts/state.md and schemas/state.json first — they are normative. ADR-004.
Decide the persistence format (pretty JSON file under the data dir) and atomic write
(tmp + rename). Keep ds-state free of IPC/socket code so ds-daemon can embed it.

## Files and boundaries

Only `touches`: `crates/ds-state/`, `schemas/state.json` (only if strictly needed —
prefer conforming to the existing schema), `tests/state/`.

## Acceptance

Unit tests prove: fresh load = empty controls/bindings/plugins and validates against
the schema; set bumps rev and notifies; transaction rolls back on failure; telemetry
never persists nor bumps rev.

## Verification

`cargo test -p ds-state`; `sh tests/fixtures/validate.sh` → ALL CHECKS PASSED;
`sh tools/check.sh`; `python3 tools/tickets.py validate`.

## Risks

Schema/code drift — the fixture gate catches it; keep both in one commit.

## Definition of done

PR merged, tests green, empty-state invariant machine-checked, board updated.
