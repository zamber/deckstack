## Context

docs/AGENT-WORKFLOW.md §Roles fixes two roles: worker and owner/steward. The steward
triages the ready set, assigns/claims, checks file collisions, reviews PRs, runs
acceptance, requests changes, merges, updates the board, unblocks, and escalates
architecture conflicts to the owner. It never implements feature tickets.

## Goal

Make the steward role concrete: a Vibe agent definition plus a launcher script, with a
written review checklist, so board triage and PR review are repeatable.

## Scope

- `agents/deckstack-steward.md`: the steward role prompt. Must state: does not
  implement feature tickets; triage loop (`tools/tickets.py ready`, `recover`,
  collision check against doing tickets); claim/assign via `tools/tickets.py claim`;
  PR review via `tools/pr.sh review` with verdict into `prs/<id>.md`; acceptance =
  `sh tests/fixtures/validate.sh` (ALL CHECKS PASSED) + `cargo test --workspace` +
  `python tests/conformance/run.py` + ticket acceptance; merge only approved PRs via
  `tools/pr.sh merge`; keep main green and the board truthful; escalate contract
  conflicts and scope-rule doubts to the owner (never silently relax
  docs/00-scope.md); protected files check (`git diff main -- BRIEF.md docs/discovery
  docs/reviews` empty).
- `tools/steward.sh`: wrapper that runs `vibe` with `agents/deckstack-steward.md` and a
  given task in the repo workdir; if `vibe` is unavailable, print the documented command
  instead of failing.
- Update `docs/AGENT-WORKFLOW.md` only to reference the new files (protocol itself is
  already written; do not redesign it).

## Out of scope

The scripts themselves (DS-002), the tool (DS-001, done), check.sh (DS-003). No feature
code.

## Implementation notes

Read docs/AGENT-WORKFLOW.md fully, plus tickets/README.md (roles, state machine). The
steward prompt must include the report shape (status, what works, what is not done,
next step, proving command) and the commit format. Keep the prompt operational, not
aspirational.

## Files and boundaries

Only the `touches` list. Do not edit BRIEF.md, docs/discovery/, docs/reviews/.

## Acceptance

A human or supervising agent can read agents/deckstack-steward.md and run the triage
loop without asking questions; `sh tools/steward.sh "triage the ready set"` either
starts vibe or prints the exact command.

## Verification

`bash -n tools/steward.sh`; run `sh tools/steward.sh --help`; `python3
tools/tickets.py validate` green after merge.

## Risks

Steward prompt drift (doing work instead of reviewing) — mitigate with an explicit
"does not implement feature tickets" rule and the escalation path.

## Definition of done

PR merged; steward agent + launcher committed; DS-006 can then validate that the
steering docs match reality.
