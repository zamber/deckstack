## Context

docs/50-repo-topology.md §6 and docs/AGENT-WORKFLOW.md fix the protocol: one worktree
per ticket under `.worktrees/<id>` from `main`, branch `ticket/<id>`, a local bare
review remote `.review.git` (remote name `review`), and a committed PR record
`prs/<id>.md`. The board tool (DS-001, done) already tracks branch/worktree/pr fields —
these scripts are what fills them.

## Goal

Implement the shell scripts that make the protocol one-command-per-step, plus the
`prs/` scaffold, and prove them with the DS-000 smoke ticket.

## Scope

- `tools/setup-review-remote.sh`: `git init --bare .review.git`, add remote `review`
  if absent, push `main`. Idempotent.
- `tools/wt.sh`: `new <id> [--owner NAME]` — require clean main, ticket ready with deps
  done (ask `tools/tickets.py`), no `doing` collision; claim on main with a
  coordination commit; `git worktree add .worktrees/<id> -b ticket/<id> main`; print
  next-step instructions. `list` — show worktrees vs board state. `remove <id>` —
  remove worktree and delete branch after merge.
- `tools/pr.sh`: `submit <id>` (run inside the worktree; require branch `ticket/<id>`,
  clean tree, ≥1 commit ahead of main; write `prs/<id>.md` from `prs/TEMPLATE.md` with
  base/head, commits, diffstat, tests run, risks; commit it on the ticket branch; push
  to `review`; print the PR path). `review <id>` (run on main; fetch; show
  `git diff main...ticket/<id>`; run `tools/check.sh` in the worktree; append a verdict
  section to `prs/<id>.md`; commit on main as a coordination commit). `merge <id>`
  (require approved verdict; rebase ticket branch on main; run `tools/check.sh`; merge
  `--no-ff`; `tools/tickets.py state <id> done` on main; commit the board; remove
  worktree; delete branch; push main to `review`). `list`.
- `prs/README.md` + `prs/TEMPLATE.md`: PR record = durable review state (ticket, owner,
  base/head, commits, diffstat, acceptance commands + results, reviewer verdict
  approved/changes-requested, risks, merge commit).
- `.gitignore`: already ignores `.worktrees/`, `.review.git/`, `tickets/.lock`; ensure
  `prs/` is NOT ignored (records are committed).

## Out of scope

tools/check.sh and CI (DS-003) — pr.sh review/merge call `tools/check.sh` if present and
must degrade gracefully until DS-003 lands. The steward agent definition is DS-005.
No feature code.

## Implementation notes

Read docs/AGENT-WORKFLOW.md (full protocol) and docs/50-repo-topology.md §6 first.
Bash, `set -euo pipefail`, stdlib git only. Scripts must work from any cwd inside the
repo (derive ROOT from the script path). Every script prints the exact next command.
Keep commit messages in the `ticket(DS-XXX): …` format with the Vibe trailer.

## Files and boundaries

Only the `touches` list: the three new tools scripts, `prs/README.md`,
`prs/TEMPLATE.md`, `.gitignore`. Do not edit tools/tickets.py unless a bug blocks you —
if so, commit the fix separately and explain in the PR record.

## Acceptance

The DS-000 smoke flow runs end to end with these scripts: claim → `wt.sh new` → edit
`docs/workflow-smoke.md` → commit → `pr.sh submit` → steward `pr.sh review` (approve)
→ `pr.sh merge` → file on main, ticket done, worktree removed, no stale branches.
