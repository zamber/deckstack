## Context

Phase 3 exit criterion (docs/60-roadmap.md): 32 fps panel push sustained 60 s on
throttled vdev, `dropped` counted, rev delta 0, control p99 ≤ 10 ms. Budgets live in
docs/30-testing.md §5 (query-under-load, frame-push-no-state-churn, stream-throughput,
memory soak, harness sensitivity). The bench harness crate `ds-bench` is in the repo
topology (docs/50-repo-topology.md §1); DS-020 landed the query-under-load skeleton.

## Goal

A repeatable `cargo bench -p ds-bench` suite that proves the phase-3 streaming budgets
on ds-vdev (no hardware), wired into CI later by DS-082.

## Scope

- `crates/ds-bench/`: benches `stream-32fps-query-p99` (32 fps × 60 s push while looping
  `get /controls/keys/0`), `frame-push-no-state-churn` (S1: rev delta 0, zero /controls
  events, telemetry ≤ 1 Hz), `stream-throughput` (throttled vdev: ≥ 32 fps accepted,
  dropped == sent − accepted), `memory` (10 min soak, RSS growth < 100 MB),
  `harness-sensitivity` (40 ms/write throttle must push p99 > 100 ms on a synchronous
  build).
- ds-vdev `--throttle-kbps` (~2.1 MB/s) and `--drop-after` knobs (DS-017/DS-035) are
  the load generators.
- `docs/30-testing.md`: only to record the exact bench commands/settings used; budgets
  already documented there.

## Out of scope

The frame service itself (DS-031), encoder (DS-030), CLI (DS-032), vdev throttle
implementation (DS-035), hardware 24 fps push (DS-026), CI gates (DS-082), LED soak
OPEN O2 (separate; must land before phase-3 exit per m11).

## Implementation notes

Read docs/30-testing.md §5, docs/60-roadmap.md phase 3, docs/components/virtual-device.md.
Benches boot their own ds-vdev + daemon on tmp paths (reuse tests/conformance process
helpers from DS-018). Use generous-but-real budgets; a bench that never fails is
worthless — the sensitivity bench proves the harness can detect the synchronous-paint
regression.

## Files and boundaries

Only `touches`: `new:crates/ds-bench/`, `docs/30-testing.md` (append bench command
reference only). Do not edit `tests/conformance/` (DS-018 area) or the daemon frames
modules.

## Acceptance

All benches run green within budgets on a fresh CI-like machine; outputs recorded in
prs/DS-033.md; the sensitivity bench demonstrably fails a deliberately synchronous
variant (run once locally, evidence in PR notes).

## Verification

`cargo bench -p ds-bench` exit 0 within budgets; fixture gate; workspace tests;
conformance; check.sh; board validate — see metadata.

## Risks

Flaky timing on loaded CI runners — budgets have headroom, and flakes are recorded, not
retry-looped (docs/AGENT-WORKFLOW.md escalation). Golden-frame drift — coordinate with
DS-030 fixtures.

gates.
