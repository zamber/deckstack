## Context

ds-device is the driver core over mh-device (ADR-010): transports (virtual now, real HID
in DS-021), the module report codec, and chunk reassembly for image pushes. The virtual
transport is what ds-vdev (DS-017) speaks, so CI needs no hardware (ADR-015).

## Goal

A `ds-device` crate with a transport trait, a virtual transport, and the report codec
with tests — everything the daemon needs to talk to "a device" before real HID exists.

## Scope

- Transport trait: open/close by URI (`virtual:<path>` now, `hid:` later in DS-021),
  send/receive reports, reader thread interface.
- Virtual transport: connects to a Unix socket speaking the report codec (ds-vdev
  implements the other end in DS-017).
- Report codec: encode/decode module reports (descriptors, key images as chunks),
  reassembly of chunked transfers with sha256 verification.
- Tests: codec round-trips, reassembly of split/oversized/duplicate chunks, sha
  mismatch rejection.

## Out of scope

Real HID (DS-021), handshake/safe builders (DS-022, phase 2), hot-plug (DS-023),
guard/handback (DS-024), vdev itself (DS-017).

## Implementation notes

Read docs/components/device-driver.md and docs/components/virtual-device.md. Depend on
mh-device per ADR-010 (git dep, pinned rev) and on ds-protocol (DS-010) for builders —
if DS-010 is not merged yet, depend on mh-protocol directly and note the swap. Keep the
virtual transport byte-compatible with what ds-vdev will serve (define the socket
protocol in docs/components/virtual-device.md if it is not already exact).

## Files and boundaries

Only `touches`: `crates/ds-device/`, `docs/components/virtual-device.md` (only if the
socket protocol needs pinning).

## Acceptance

cargo tests green: codec round-trip, chunk reassembly incl. error cases, virtual

## Risks

Virtual/real divergence — keep the transport trait strict so DS-021 is a new
impl, not a refactor; if hardware behaves differently from vdev, fix the virtual
model first (docs/AGENT-WORKFLOW.md escalation rule).
