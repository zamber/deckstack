## Context

The device task only forwarded image and knob/roller LED changes. `/controls/keys/*/brightness`
and `/controls/dial/brightness` were stored by the state task but dropped by `plan_push`; the
base ring had no state path at all. After the HID feature-report fix, software mode and
backlight reports reach the hardware, so the missing mapping was the remaining blocker.

## Goal

The keys panel backlight, the dial backlight and the base ring colour/brightness all follow
the values written by the Salon micro-app.

## Scope

- `DeviceAction::Backlight` for keys/dial brightness (`03 34` / `03 44` feature reports).
- `DeviceAction::BaseLed` for the base ring (`02 2C/2D/2E`, target 0) carrying mode, colour and
  brightness so animated effects can be added later.
- `plan_push` arms and `device_task` cache/kind/send arms.
- `/controls/base/led` in `schemas/state.json` and the write-path vocabulary in
  `crates/ds-state/src/path.rs`.
- Unit tests for the brightness and base LED mappings.

## Out of scope

Animated base effects (breathing/wave/rainbow), per-key backlight colour and the reporting
CLI (DS-108).

## Implementation notes

Keys/dial brightness is a feature report, not an output report; it relies on the
`HidTransport::send` dispatch fix (52b4803). The base LED is M0 family and always available;
`LedTarget::All` maps to `(0,0)` for `ModuleKind::Base`. The app writes the leaf object at
`/controls/base/led`, so `plan_push` parses the value directly, not `value["led"]`.

## Files and boundaries

Only the four `touches`. Protected: `BRIEF.md` R1-R12, `docs/discovery/`, `docs/reviews/`.

## Acceptance

- Backlight and BaseLed actions are emitted and sent; state and tests pin the paths.
- `ds set /controls/base/led` succeeds and the journal shows a `pushed BaseLed` line.
- No other control path changes behaviour.

## Verification

`cargo test -p ds-daemon --lib` (199 passed); `cargo test -p ds-state`;
`ds set /controls/base/led --json '{"mode":"static","color":"#ff8800","brightness":40}'` →
`pushed BaseLed { mode: Static, rgb: [255, 136, 0], brightness: 40 }` at 16:29:51;
`pushed Backlight { kind: Keys, percent: 76 }` / `Dial` at 16:28:40.
Camera capture: `~/repos/salon-deck/deck-verify.jpg`.

## Risks

Feature reports require the 52b4803 transport dispatch; without it the backlight writes are
silent no-ops. Base mode effects are untested on hardware beyond `static`.

## Definition of done

Backlight and base-ring state paths are documented, mapped and verified on the real deck.
