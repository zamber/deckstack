## Context

Phase 5 SDK. docs/contracts/plugins.md §8 defines the SDK shape: `ds-plugin-sdk`
(Rust) and `ds-plugin-py` (Python, DS-052) speak the same newline-JSON wire protocol
(§1). The host is DS-050; the router's `plugin` step is DS-042. The crate is in the
workspace topology (docs/50-repo-topology.md §1) and publishes as its own repo later
(subtree split, DS-083).

## Goal

A published-shape Rust crate that makes writing a deckstack plugin in Rust boring and
correct: one macro/function to register actions, typed effects, and a tested protocol
implementation.

## Scope

- `crates/ds-plugin-sdk/`: wire protocol client (hello/register/event/invoke/effects/
  request/reply framing per plugins.md §1), manifest builder validated against
  schemas/plugin-manifest.json, action registry with params validation, effect
  builders, `http()` issuing `request kind:"net"`, state get/set helpers, logging to
  stderr.
- `tests/contract/plugins/`: protocol contract tests against a mock host (recorded
  message sequences validated against schemas where applicable).
- README for the crate with a minimal example (mirrors plugins.md §7).

## Out of scope

The host (DS-050), Python wrapper (DS-052), abuse tests (DS-053), packaging/publish
(DS-054/DS-083).

## Implementation notes

Read docs/contracts/plugins.md §1/§8, schemas/plugin-manifest.json. Keep the SDK
dependency-light (serde/serde_json only). Protocol versioning: `protocol: 1` in hello;
mismatch → host kills the plugin (DS-050 behavior) — SDK must surface that cleanly.

## Files and boundaries

Only `touches`: `new:crates/ds-plugin-sdk/`, `new:tests/contract/plugins/`. Do not edit
`crates/ds-daemon/` (DS-050), `plugins-py/` (DS-052), schemas (contract-owned; propose
changes via steward if needed).

## Acceptance

`cargo test -p ds-plugin-sdk` green incl. a full scripted session against a mock
host; crate builds standalone (`cargo build -p ds-plugin-sdk`).

## Verification

cargo tests for the crate, fixture gate, workspace tests, conformance, check.sh,
board validate — see metadata.

## Risks

Protocol drift between SDK and host — contract tests on both sides must use the same
recorded corpus (tests/fixtures/ipc-examples.json style); coordinate via steward.

## Definition of done

PR merged; a Rust plugin can be written against the SDK and pass protocol tests; DS-054
can use it for a Rust example if desired.

## Notes

Publishing as its own repo (release/ds-plugin-sdk subtree split) is DS-083.
