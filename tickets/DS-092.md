## Context

HANDOFF.md known issue 2: `tickets.py` has no way to extend `touches`. DS-012 needed
`new:crates/ds-client/` added by hand on main, and DS-013/DS-016/DS-017 needed wiring
paths (`crates/ds-ipc/src/lib.rs`, root `Cargo.toml`, `bins/.../`) added mid-flight.

## Goal

`python3 tools/tickets.py add-touch <id> --add <entry> [--add ...]` updates the ticket's
touches through the tool (lock, validation, sync), with the same collision rules as claim.

## Scope

- New `add-touch` subcommand: rewrite only the JSON block's `touches`, update `updated`,
  run the same validation as `sync`, and regenerate BOARD/GRAPH/index.
- Refuse: unknown id, duplicate entry, entry that does not exist / has no existing parent
  and no `new:` prefix, and (for a doing ticket) an entry already owned by another doing
  ticket.
- Docs: AGENT-WORKFLOW "if scope must change" section and tickets/README.

## Out of scope

Artificially widening touches to cover a diff after the fact; removing entries (a
separate command if ever needed); changing the collision checker semantics.

## Implementation notes

Follow the existing `cmd_assign`/`cmd_claim` shape (`Lock(exclusive=True)`, load, mutate,
`sync_outputs`). Keep the writer that rewrites the fenced JSON block authoritative; do
not touch the body text.

## Files and boundaries

Only the three paths in `touches`.

## Acceptance

`add-touch` on a real ticket adds the entry, prints the new touches, and leaves
`validate` OK; duplicates and collisions exit nonzero with a clear message.

## Verification

`python3 tools/tickets.py validate`; `sh tools/check.sh`; the command exercised on a
scratch ticket in the PR record.

## Risks

Rewriting metadata can reorder JSON keys; keep key order stable to keep diffs small.

## Definition of done

PR merged, command tested, docs updated, HANDOFF known issue 2 closable.
