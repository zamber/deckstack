## Context

docs/30-testing.md defines the black-box conformance layer; AGENTS.md lists
`python tests/conformance/run.py` as the no-hardware suite (vdev). Scope invariants
(empty state, no `ds migrate`, no web UI) must be asserted here, not just documented.

## Goal

A pytest-based harness under `tests/conformance/` with a `run.py` entry point that
boots a daemon against ds-vdev (or an in-process mock where vdev is not ready) and
runs the phase-1 conformance cases.

## Scope

- `tests/conformance/run.py`: discovers and runs the suite; manages a temp data dir,
  starts ds-vdev + ds daemon (or mocks if binaries absent — degrade with a clear SKIP,
  never a silent pass), tears down, prints a summary, exit code = failures.
- pytest suite: empty-state invariant; get/set/watch round-trips over the CLI and raw
  IPC; rev semantics; NDJSON shape validation against schemas/ipc-message.json;
  `ds migrate` exits 1; error envelopes and exit codes.
- `tests/requirements.txt`: add pytest (+ jsonschema if needed).
- Harness must run with no hardware and in CI via tools/check.sh.

## Out of scope

Hardware smoke (DS-026), camera verification (DS-027/028), safety conformance
(DS-029), perf gates (DS-082, later), streaming conformance (phase 3 tickets add cases
to this harness — keep it extensible).

## Implementation notes

Read docs/30-testing.md and docs/contracts/*. The harness talks to the system only
through the CLI and the socket (black box). Keep cases data-driven so phase 3-6
tickets just add case files.

## Files and boundaries

Only `touches`: `tests/conformance/`, `tests/requirements.txt`.

## Acceptance

`python tests/conformance/run.py` exits 0 with the invariant cases present and green
against the phase-1 stack (or clearly SKIPped with reasons before DS-015/017 land —
but the harness itself must run).

## Verification

The run.py exit 0; fixture gate; check.sh; board validate.

## Risks

Flaky process management — use timeouts and tmp dirs; never leave daemons running.

## Definition of done

PR merged, harness green in CI via check.sh, invariants asserted.
