## Context

DS-093 fixed the fixture gate and found that `schemas/state.json` maps such as `controls.keys`
use `patternProperties` without `additionalProperties: false`, so a non-matching key name is
accepted by the normative schema. DS-093 removed two negative fixtures rather than weaken the
gate (see prs/DS-093.md) and left the schema gap open.

## Goal

The state schema rejects out-of-range key/knob/roller indices at object level.

## Scope

- `additionalProperties: false` (or a closed `propertyNames` pattern) on every indexed map in
  `controls` and any similar map, with the index ranges stated in the descriptions.
- Restore the `keys.99` / `keys.15` negatives in tests/fixtures/validate.js.
- docs/contracts/state.md: index ranges for keys (0-14), knobs, rollers, dial.

## Out of scope

Changing the shape of the state document; CLI validation (DS-062).

## Implementation notes

Read prs/DS-093.md and the schema's `$defs/controls`. Check the example document in
tests/fixtures/validate.js still validates; device layout in crates/ds-device/src/module.rs.

## Files and boundaries

Only the three paths in touches. Contracts are normative: schema and doc in the same commit.

## Acceptance

The restored negatives are rejected; the fixture gate and check.sh are green.

## Verification

`sh tests/fixtures/validate.sh` -> ALL CHECKS PASSED; `sh tools/check.sh` -> CHECK: ALL GREEN;
`python3 tools/tickets.py validate` -> OK.

## Risks

`additionalProperties: false` on a map that the daemon writes freely would reject valid state;
list every allowed property first and keep the example document green.

## Definition of done

PR merged, S8 enforced at object level, negatives back.

## Notes

Low risk, contract-only change.
