## Context

Phase 4 (docs/60-roadmap.md): events, bindings, actions. Contract:
docs/contracts/actions.md §1-2 (topics, event shape, routing model S2). Component:
docs/components/event-router.md. The daemon skeleton (DS-015), CLI incl. `emit`/`events`
verbs (DS-016 + DS-041), and vdev `inject` (DS-017) exist by the time this runs.

## Goal

The in-daemon event bus and router: every event source (device input, CLI emit,
system) lands on a topic, subscribers and the binding router get it in order, and the
dispatch latency budget is instrumented.

## Scope

- `router/bus.rs`: in-daemon pub/sub (topics, subscriber queues with `dropped`
  counting per ipc.md §5 >1000 queued → E_LIMIT close), event struct
  `{topic, ts_ms, payload, rev}`.
- `router/topics.rs`: topic vocabulary + validation (actions.md §1), control/gesture
  parsing for `keys.0`, `dial`, `knobs.0`, `faders.2`, `rollers.1` ×
  `down|up|long|double|rotate|slide`.
- `router/mod.rs`: device input reports → `deck/control/*` events; `deck/device/*`
  and `deck/system/*` lifecycle events; `emit` op → `app/<sender>/<topic>`; lookup
  exact then `prefix/*` wildcard against `/bindings` in array order (binding execution
  itself is DS-042).
- `ds events --ndjson` subscription verb support on the CLI side only if not already in
  DS-016 — coordinate, prefer consuming.
- Conformance cases under `tests/conformance/events/`.

## Out of scope

Bindings storage/CLI (DS-041), step execution (DS-042), exec policy (DS-043), focus
ingest (DS-044), plugin host (phase 5).

## Implementation notes

Read docs/contracts/actions.md, docs/components/event-router.md, schemas/ipc-message.json
(emit/subscribe ops), ADR-007. Keep the bus lock-free or single-lock and never held
across IPC writes to subscribers; event → dispatch p99 ≤ 5 ms (actions.md §5) —
measure with a histogram in telemetry.
