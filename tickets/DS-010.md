## Context

The device layer reuses mh-protocol/mh-device as git dependencies (ADR-010). ds-protocol
is the single crate that re-exports the mh-protocol builders and adds the safety layer:
the mh-protocol safety rules (forbidden HID commands stay unrepresentable; never
backlight-0 the dial; software-mode handshake before reads) must be enforced by types
and covered by tests, per AGENTS.md invariants.

## Goal

`crates/ds-protocol` compiles, re-exports mh-protocol builders with wire version 1, and
has tests proving forbidden commands cannot be represented and the safe builders behave.

## Scope

- Add mh-protocol as a git dependency of ds-protocol only (ADR-010); pin the rev.
- Re-export the builder API; add thin safe wrappers where the upstream API allows
  unsafe shapes.
- Safety tests under `crates/ds-protocol/tests/` (and/or `tests/protocol/`): forbidden
  command set unrepresentable (compile-fail style tests via doc-tests or explicit
  builder rejection), backlight-0 rejected, handshake-before-read ordering enforced by
  the type state.

## Out of scope

Real HID transport (DS-021/DS-022), frame streaming (DS-013), any daemon code.

## Implementation notes

Read docs/components/device-driver.md, ADR-010, and the AGENTS.md invariant list.
Wire version `protocol: 1` per docs/contracts/ipc.md §3. Keep the crate dependency-light
so other crates can depend on it without pulling hidapi.

## Files and boundaries

Only `touches`: `crates/ds-protocol/`, `tests/protocol/`. Do not edit schemas/ or
docs/contracts/ (owned by DS-011/DS-012/DS-013).

## Acceptance

`cargo test -p ds-protocol` green with the safety tests present and meaningful (they
must fail if a forbidden builder is made representable).

## Verification

Acceptance commands in the worktree; `sh tools/check.sh`; board validate.

## Risks

Upstream mh-protocol API drift — pin the git rev and record it in NOTICE.

## Definition of done
