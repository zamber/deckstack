## Context

Phase 6 (docs/60-roadmap.md): ds-mcp gives coding agents the deck as MCP tools over the
same API (BRIEF goal; precedent `hubdeck --mcp` stdio JSON-RPC). Component spec
docs/components/mcp-bridge.md: external binary, shares ds-client, daemon keeps no
agent-specific surface (R4). Events from the DS-040 bus stream as MCP notifications via
deck_watch.

## Goal

A `ds-mcp` binary that a spawned MCP client can drive: `tools/list` plus one working
`deck_set` against the daemon on vdev — the phase-6 agent-surface exit.

## Scope

- `bins/ds-mcp/`: stdio JSON-RPC 2.0 framing, initialize/tools/list/tools/call, the
  tool set above, each mapped to one control-socket op (ipc.md §4), token auth, 10 s
  timeout, error mapping to JSON-RPC errors with the E_* code in the message.
- `deck_watch`: opens a subscription and forwards events as MCP notifications
  (NDJSON internally); client cancel closes it.
- `tests/conformance/mcp.py`: spawned-client conformance incl. tools/list shape and one
  deck_set assertion.

## Out of scope

ds-focus (DS-060), CLI self-description tests (DS-062), client helper lib (DS-063),
WS/HTTP adapter (DS-074), any UI.

## Implementation notes

Read docs/components/mcp-bridge.md, docs/contracts/ipc.md §3-4, docs/contracts/cli.md
(verbs map 1:1). Keep the bridge thin — no state, no caching, no policy. Hand-rolled
JSON-RPC (boring on purpose). Discovery: an agent must find every tool from tools/list
alone (R1/R10).

## Files and boundaries

Only `touches`: `new:bins/ds-mcp/`, `docs/components/mcp-bridge.md` (gap fixes only),
`new:tests/conformance/mcp.py`. Do not edit `bins/ds/`, `crates/ds-daemon/`,
`crates/ds-client/` (consume it).

## Acceptance

mcp.py green on vdev: initialize, tools/list contains all ten tools, deck_set changes
state, deck_watch notification observed on an injected event, daemon-down case returns
E_UNREACHABLE with hint.

## Verification

## Risks

record any version assumptions in the PR. Notification storms — deck_watch honors the
ipc.md §5 subscriber limits.
