## Context

DS-028 landed the golden harness and the goldens, but every golden carries a
`skip_reason`: this M4315 unit keeps the last pushed colour per key index (a fresh daemon
data dir is not a fresh device) and ignores the LED `off` mode, so the same manifest state
renders differently minutes later. Measured 2026-11-24: key0 matched 17/17 targets
immediately after recording, then failed on the untouched keys 1-14 and `led:0`; panel
15/17; led 3/17.

## Goal

Make a golden state fully specify the device: pin every key index and every LED ring on
every golden, find a sequence that really clears the LED rings, then flip the goldens from
documented skips to strict checks that pass repeatedly.

## Scope

- `tools/verify/golden/manifest.json`: every golden's `state` sets all 15 key images and
  the knob/roller LEDs explicitly; drop each `skip_reason` only when the golden passes
  strict twice.
- `tools/verify/golden/run_golden.py`: any harness change needed for the new states (for
  example a pre-run "clear all keys/LEDs" step, or verifying the settled state via
  `ds get` before capture).
- `docs/90-verification.md`: the confirmed procedure, the strict mode and what it means.

## Out of scope

Daemon/device semantics changes (the LED `off` handling is a device property; if it cannot
be cleared in software, record that with evidence), more golden targets, CI camera jobs.

## Implementation notes

The deck is reachable at `hid:` after the usbhid rebind (see memory / docs/90-verification.md
§usbhid). `run_golden.py --record` regenerates calibration and every golden; `--only`,
`--strict`, `--keep DIR` exist. Test LED-off candidates directly with `ds set
/controls/knobs/0/led --json '{"mode":"static","color":"#000000","brightness":0}'` versus
`{"mode":"off",...}` and capture to compare.

## Acceptance

`run_golden.py --strict` exits 0 twice, ten minutes apart, on the reference pose; the
manifest carries no `skip_reason`.

## Verification

The commands above, plus check.sh and board validate.

## Risks

Lighting drift can still fail a strict check; if so, record the measured cause and keep the
golden documented rather than loosening the tolerance past the measured noise.

## Definition of done

PR merged; a strict golden run is the documented, repeatable camera gate.

## Files and boundaries

Only the paths in `touches`. `docs/reviews/` and `docs/discovery/` are protected; daemon and
device code are out of scope for this ticket.
