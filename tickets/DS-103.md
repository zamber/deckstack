## Context

The 2026-11-24 fresh-agent exercise needed to restore keys on exit and could not find a clear
operation: there is no delete verb; `ds set /controls/keys/2 null` is E_SCHEMA exit 1 (null
is not a string); `ds set /controls/keys/2 '{}'` empties the object and is the actual clear,
discovered only by trial. `docs/microapps.md` §2 gives the key shape
`{image, label, brightness}` but never says how to remove or restore a path, and
`ds set --help` does not mention it either.

A micro-app that paints keys and restores them on exit (the documented cleanup pattern) hits
this on its first run.

## Goal

Clear and restore semantics are discoverable from `ds set --help` and the authoring guide;
a worker does not have to probe for the operation that empties an object path.

## Scope

- `bins/ds/src/help.rs`: one line in the `set` help next to the value examples — setting `{}`
  clears an object path; `null` is E_SCHEMA exit 1. Stay within the per-verb ~25-line budget.
- `docs/microapps.md` §2: a short "Clearing and restoring a path" paragraph plus a 5-8 line
  snapshot/restore snippet (one `ds get`, then `ds set <path> <old>` or `{}`). Mention the
  key case explicitly and that paths that did not exist are cleared with `{}`.
- `tests/conformance/cli/`: assert the help text contains the clear line and that
  `ds set /controls/keys/0 null` returns exit 1 with code `E_SCHEMA`; assert `{}` leaves an
  empty object and exit 0. Reuse the existing vdev boot in that suite.

## Out of scope

A new `ds delete`/`ds unset` verb or a `--clear` flag. If the empty-object write turns out to
be insufficient for some path kinds (e.g. control LEDs), record it here or split a ticket.

Read `bins/ds/src/help.rs` (`set` section), `docs/contracts/cli.md` for the help budget and

## Risks

Setting `{}` may be wrong for paths whose schema has required fields (none today for
`screenControl`, but check `/controls/*` sub-objects and `/policy`). If the schema rejects
`{}` anywhere an app needs to clear, document the per-path alternative instead of inventing
one.
