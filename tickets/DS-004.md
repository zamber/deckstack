## Context

Phase 0 exit criterion (docs/60-roadmap.md): `cargo build --workspace` green. The
layout is fixed by docs/50-repo-topology.md §1: virtual manifest at the root, crates
under `crates/`, CLI/sender bins under `bins/`. mh-protocol/mh-device are git
dependencies (ADR-010) — wiring them in is phase 1 (DS-010/DS-014), not here.

## Goal

Create a compilable Cargo workspace skeleton with one stub crate per planned component
so phase 1 tickets can fill in real code in parallel without layout churn.

## Scope

- Root `Cargo.toml` (virtual manifest, `[workspace]` members = `crates/*`,
  `bins/*` when they appear; workspace lints).
- Stub crates each with `Cargo.toml` (own semver version per docs/50-repo-topology.md
  §3) and a `src/lib.rs` with a doc comment naming the component spec in
  `docs/components/`: ds-protocol, ds-device, ds-state, ds-ipc, ds-client, ds-daemon,
  ds-vdev (ds-plugin-sdk, ds-bench are phase 5/3 — create only if trivial, else leave
  to their tickets).
- `rustfmt.toml` and `clippy.toml` at the root with the project defaults.
- `LICENSE` (dual license per ADR-010) and `NOTICE` (attribution placeholder for
  mh-protocol/mh-device git deps).

## Out of scope

Any real logic, mh-* git dependencies, bins/, tests beyond `cargo test --workspace` on
stubs. Feature code belongs to phase 1 tickets.

## Implementation notes

Read docs/50-repo-topology.md §1/§3 and ADR-008/ADR-010. Keep stubs minimal (lib.rs
with docs only, maybe one `#[cfg(test)]` smoke test per crate so `cargo test
--workspace` is meaningful). Do not add dependencies yet — the workspace must build
offline with zero external crates.

## Files and boundaries

Only the `touches` list. Do not edit schemas/ or docs/contracts/ (owned by their
phase 1 tickets).

## Acceptance

`cargo build --workspace`, `cargo fmt --check`, `cargo clippy --workspace -- -D
warnings`, `cargo test --workspace` all green; `sh tools/check.sh` picks up the cargo
steps automatically.

## Verification

The acceptance commands above, run in the ticket worktree, plus
`python3 tools/tickets.py validate`.

## Risks

Stub crates that later get real deps may need Cargo.toml edits — that is expected and
owned by the phase 1 ticket that fills the crate.

## Definition of done

PR merged; workspace builds green; check.sh runs the cargo gates; board updated.

This is the root dep for DS-010..DS-014 (they run in parallel after this lands).
