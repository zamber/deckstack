## Findings

Live Bazzite KDE Plasma 6 Wayland session evidence (this run host, hardware/DE run — not CI):

- `busctl --user introspect org.kde.KWin /KWin` shows the active-window interface
  `org.kde.KWin.queryWindowInfo -> a{sv}` (plus `/Scripting org.kde.kwin.Scripting`);
  `busctl --user list` shows the name owned by kwin_wayland. The kwin backend therefore
  polls `org.kde.KWin /KWin org.kde.KWin.queryWindowInfo` via zbus (no script file needed).
- `wayland-info` on `wayland-1` shows NO `zwlr_foreign_toplevel_manager_v1` /
  `ext-foreign-toplevel-list-v1` global on KDE, so `--backend wlr` on this session exits 3
  with "available: kwin" and autodetect selects `kwin` (measured answer to OPEN O1 on
  Bazzite: KWin D-Bus primary, wlr-foreign-toplevel for wlroots compositors only).
  `ext-foreign-toplevel-list-v1` (staging) carries no activation state (title/app_id/
  identifier/done/closed only), so `zwlr_foreign_toplevel_manager_v1` (with `activated`)
  is the wlr backend.
- `ds-focus --once` on this session: backend kwin selected, `queryWindowInfo` answers
  UserCancel (nested container has no focused window) -> "no focused window right now",
  exit 0 — the no-focus path, not an error.
- vdev emit latency measured in conformance smoke: `emit_ms=0.1` with 2 subscribers; the
  watch event's ts_ms equals the emit ts_ms (same-millisecond delivery on vdev). Settle
  coalescing/dedupe/deadline wakeups are unit-tested (26 tests in `cargo test -p ds-focus`).
- The <= 500 ms end-to-end "focus a window -> bound key recolours" number needs an
  interactive DE session with a binding installed (DS-041/042 + DS-044 mirror); this run
  host is a nested/headless KWin, so that number is NOT claimed here — pending a real
  Bazzite desktop session.
