## Deferred to DS-042 (step execution)

This PR stores and validates bindings only; it deliberately does NOT execute steps:

- **Step execution / the binding engine** (matching bindings on a published event,
  evaluating `when` against state `path` or event `payload`, running `steps`
  sequentially, `emit`-recursion cap 10, `deck/system/binding-error` on failure) is
  DS-042. `ds bind` accepts and schema-validates the step shapes (`set`, `emit`,
  `plugin`, `exec`, `sleep` — non-empty `steps`, no code fields: `{"do":"eval",…}` is
  rejected) but nothing runs on an event yet; the conformance case 080 asserts exactly
  that (topic event published, no state change, stored shape intact).
- **Exec runtime policy** (allow/deny check against `/policy/exec/*`, rlimits,
  fire-and-forget spawn) is DS-043; the schema shape (`argv[0]` absolute) is already
  enforced here.
- The router itself (DS-040) is untouched; committed `/bindings` changes already flow
  to the bus as state events (one per committed transaction).
