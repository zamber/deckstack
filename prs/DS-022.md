## Risks


Handshake timeouts on flaky USB — bounded retries, then a clear error (feeds DS-023's
unresponsive handling). On this machine the real deck enumerates but cannot be opened by
the test user (udev/uaccess, DS-025), so the on-hardware handshake run is still owed; the
state machine and wire bytes are covered by the mock-transport unit tests.


## Findings

- No ds-protocol API change was needed: all required builders (images, LED, backlight,
  brightness) already exist behind the safe surface; backlight-0 refusal and the forbidden
  guard are enforced again on the ds-device side (`handshake::safe` + `ensure_allowed`).
- hidapi's libusb backend reports every open failure as the useless string
  "hid_error is not implemented yet" — the real cause here was EACCES on the device node
  (verified directly). Worth remembering when reading DS-025-era failures.
