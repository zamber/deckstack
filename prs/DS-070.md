### Host gaps found (reported, NOT worked around with core changes — umbrella tickets to file)

1. `crates/ds-daemon/src/plugins/host.rs` `http_fetch` performs plain-http GET/HEAD
   only, so `lights.set` maps state onto the GET query string; POST/PUT is a host change.
2. `Plugin::refresh_state()` runs after every invoke and replaces `/plugins/<id>`
   wholesale (preserving only the `state` subtree), so `/plugins/lights/config` is not
   durable in this tree; the plugin honours it when present and falls back to the
   durable `/plugins/lights/state/config`.
3. `handle_message` does not implement the plugin->host `error` op (unknown-op
   violation; a handler-raised PluginError hangs the invoke to the 2 s E_LIMIT
   timeout), so the plugin records refusals in `/plugins/lights/state/last` instead.
4. The host answers an invoke's `effects` with a `reply` carrying the invoke's
   request_id — same id space the SDK uses for plugin->host requests (both from 1);
   the plugin bases its request ids at 1_000_000 to avoid the crossing.
